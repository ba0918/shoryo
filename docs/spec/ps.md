# 議題の一覧

`shoryo ps` は、議題とそのサーバーを一覧にするコマンド。
主な使い手は人で、LLM が画面の URL を会話に書き忘れたときに自分で URL を引き、LLM の会話が落ちて残ったサーバーを自分で止めるために使う。
LLM も、JSON の出力で同じコマンドを使える（[議題名がわからない再開](skill.md#議題名がわからない再開)）。

議題の起動とデータは [起動と往復と記録](server.md) にある。用語は [CONTEXT.md](../../CONTEXT.md) に従う。

この文書で「動いている議題」は、サーバーが動いている議題を指す。議題を[終えた](server.md#終える)かどうかとは別で、終えた議題でもサーバーが動いていれば動いている議題として出す。「止まった議題」は、サーバーが動いていない議題を指す。

## 出す範囲と対象

範囲と対象は、別々の引数で選ぶ。2 つは独立に組み合わせられる。

| 引数 | 範囲 | 対象 |
|---|---|---|
| なし | カレントディレクトリのリポジトリ | 動いている議題 |
| `-a`（`--all`） | カレントディレクトリのリポジトリ | 止まった議題も含めた全部 |
| `--all-repos` | 全リポジトリ | 動いている議題 |
| `-a --all-repos` | 全リポジトリ | 止まった議題も含めた全部 |

カレントディレクトリのリポジトリは、ほかのコマンドと同じ決まりで決める（[議題と起動](server.md#議題と起動)）。リポジトリの外では、打った場所のパスを使う。
議題がどのリポジトリのものかは、議題のデータがどのリポジトリの置き場にあるかで決める（[記録の置き場所と寿命](server.md#記録の置き場所と寿命)）。データの中のリポジトリのパスが空の議題も、これで範囲に入るかが決まる。
`--all-repos` に短い形は付けない。

`-a` では、ラウンドを出す前に止まった議題（状態のファイルがないもの）も出す。議題名とデータの置き場所だけを出し、ほかの値は空にする。

成功条件: リポジトリ A で動いている議題と、リポジトリ B で動いている議題と止まった議題があるとき、A で `shoryo ps` を打つと A の議題だけが出る。`shoryo ps -a --all-repos` では B の止まった議題も出る。ラウンドを出す前に止めた議題も `-a` で出る。
反例: `-a` を付けると範囲まで変わる。カレントのリポジトリ以外の議題が、引数なしで出る。
確かめ方: 往復のテスト。

### 範囲の外で動いているサーバーの知らせ

`--format text` で `--all-repos` を付けていないとき、範囲の外で動いているサーバーがあれば、表の最後に 1 行添える。
その行には、範囲の外で動いているサーバーの数（議題ひとつにサーバーは 1 つなので、動いている議題の数と同じ）と、`--all-repos` で出せることを書く。`-a` のときも、数えるのは動いているサーバーだけ。
範囲の中が 0 件のときは、[0 件の 1 行](#text) のあとにこの行を添える。
`--format json` では添えない。

成功条件: ホームディレクトリなどリポジトリの外で `shoryo ps` を打ち、ほかのリポジトリで 2 つ動いているとき、text の出力に 2 という数と `--all-repos` が出る。json の出力は配列だけで、数は出ない。
反例: 既定の範囲の外に残ったサーバーがあるのに、何も出ずに終わる。
確かめ方: 往復のテスト。

## 動いているかの決め方

議題が動いているかは、ほかのコマンドと同じく、議題の lock に書かれた PID のプロセスが生きているかで決める。サーバーには問い合わせない。
応答しなくなったサーバーも、プロセスが生きていれば動いている議題として出す。

成功条件: 応答しないサーバーでも、PID と URL が出る。
反例: ps が各サーバーの応答を待って遅くなる。応答しないサーバーが一覧から消え、止める手がかりがなくなる。
確かめ方: 往復のテスト。

## 止め方

ps は動いている議題のサーバーの PID を出す。人は、その PID を OS の kill で止める。
サーバーは SIGTERM で終了処理をして止まり、そのあと同じ議題を `shoryo start` で起動できる。
SIGTERM で止まらないサーバーは、人が SIGKILL で止めてよい。そのときも、死んだプロセスが残した lock は次の `shoryo start` で置き換わり、起動できる。
`shoryo stop` コマンドは変えない。

成功条件: ps が出した PID に SIGTERM を送るとサーバーが止まり、ps の引数なしの出力から消える。同じ議題の `shoryo start` が「すでに動いている」で断られずに起動する。SIGKILL で止めたときも、同じ議題の `shoryo start` が起動する。
反例: kill で止めたあと、残った lock のために同じ議題を起動できない。
確かめ方: 往復のテスト。

## 出力の形

出力の形は `--format text|json` で選ぶ。既定は `text`。
`wait` や `result` は何も指定しなくても JSON を出すが、ps は人が読む `text` が既定になる。ヘルプにこの違いを書く。

### text

人が読む表。見た目は変わってよく、ほかのツールが読む形として約束しない。表のあとの知らせや 0 件の 1 行の文面も同じ扱い。
コマンドのほかの出力と同じく英語で出す（[設定ファイル](server.md#設定ファイル)）。

列は次のとおり。

- 既定: 議題名、題名、最新ラウンド（番号と、人が送ったか、人の答え待ちか）、PID、URL
- `--all-repos` のとき: 先頭にリポジトリ（ホームディレクトリは `~` に縮める）を足す
- `-a` のとき: 更新した時刻と、終えたかどうかを足す。止まった議題の PID と URL は空にする

題名は長ければ切る。URL は切らない。

表のセルに入る値（題名、リポジトリのパスなど）に制御文字（改行、ESC など）があれば、見える形にエスケープして出す。題名は LLM が書くので、端末を操作する文字を人の端末にそのまま流さないため。JSON はこの対象ではない。

0 件のときは、表の代わりに議題がないことを 1 行で出す。

成功条件: text の出力に、動いている議題の PID と、そのまま開ける URL が出る。0 件のときも何かの 1 行が出て、終了コードは 0。題名に改行や ESC を含む議題も 1 行で出て、制御文字がそのまま出力に入らない。
反例: URL が途中で切れて開けない。0 件のとき何も出ず、動いていないのか壊れたのか区別できない。題名の改行で行が割れる。題名の ESC で端末の表示が書き換わり、違う PID が見える。
確かめ方: 往復のテスト。値が出ていることと、制御文字がそのまま出ないことだけを確かめ、列の並びや幅、エスケープの書き方は確かめない。

### json

議題 1 つを 1 要素とする配列。0 件なら `[]`。キーは次のとおりで、LLM やほかのツールが読む形として約束する。

| キー | 中身 |
|---|---|
| `repository` | リポジトリのパス |
| `topic` | 議題名 |
| `title` | 議題の題名 |
| `ended` | 議題を終えたか |
| `latest_round` | 最新ラウンドの `number` と `submitted`（人がそのラウンドを送ったか）。ラウンドがなければ空 |
| `created_at` | 議題を作った時刻 |
| `updated_at` | 議題のデータを最後に書いた時刻 |
| `data_dir` | 議題のデータの置き場所 |
| `server` | サーバーの `pid`・`url`・`started_at`（起動した時刻）・`version`（サーバーの版）。止まった議題では空 |

わからない値や取れない値は空（`null`）にし、推測で埋めない。時刻は RFC 3339 の UTC。

成功条件: 動いている議題と止まった議題を `-a --format json` で出すと、どちらも同じキーを持ち、止まった議題の `server` は `null` になる。最初のラウンドを出す前の議題では `title`・`ended`・`latest_round`・`created_at`・`updated_at` が `null` になる。そのうち動いているものは `repository` と `server` が入り、止まったものは `repository` と `server` も `null` になる（`topic` と `data_dir` だけが入る）。
反例: 取れない値を、ほかの値から推測して埋める。動いている議題と止まった議題でキーが違う。
確かめ方: 往復のテスト。

### URL の secret

URL には画面の secret が含まれる。`shoryo start` が出すものと同じで、ps は新しい秘密を出さない。

## 値の用意

ps が出す値は、議題のデータ置き場のファイルだけから読む。今のデータにない値は、次のように用意する。

- 起動した時刻、サーバーの版、リポジトリのパス: サーバーが起動したとき、動いている間だけあるファイル（今の endpoint.json）に書く。止まると消える。
- 作った時刻: 議題の状態を初めて書いたとき（最初のラウンドを出したとき）の、サーバーの時計の UTC。議題の状態に持つ（[状態データ](server.md#状態データ)）。
- 更新した時刻: 議題の状態のファイルを最後に書いた時刻。

リポジトリのパスは、議題の状態か、動いている間のファイルから読む。どちらにもなければ空にする。
この変更より前に作った議題や、前の版で起動したサーバーでは、作った時刻・起動した時刻・版が取れない。これは空にし、警告は出さない。

成功条件: 新しく作った議題では、最初のラウンドのあと `created_at` が入る。前の版で作った議題では `created_at` が `null` で、警告は出ない。サーバーを起動するとすぐ `started_at` と `version` が入る。
反例: ファイルシステムの作成時刻を作った時刻として出す。前の版の議題を読むと警告が出る。
確かめ方: 往復のテスト。

## 読めない議題

ある議題のファイルが読めない、または中身がおかしいときは、ps 全体を失敗させない。
その議題は読めた値だけで出し、読めない値は空にする。サーバーが動いていれば、PID と URL は出す。
読めなかった理由は stderr に警告として出す。終了コードは 0。

データ置き場の中のリポジトリごとのディレクトリが読めないときも、同じく ps 全体は失敗させない。そのリポジトリは飛ばして理由を警告し、ほかのリポジトリの議題を出す。終了コードは 0。
データ置き場そのものが読めないときは、出せるものがないので、理由を出して終わる（終了コード 1）。まだ一度も起動していなくて置き場がないときは、0 件として扱う。

成功条件: 壊れた状態のファイルを持つ議題が混ざっていても、ほかの議題は出て、終了コードは 0。壊れた議題のサーバーが動いていれば、その PID と URL も出る。読めないリポジトリのディレクトリがあっても、ほかのリポジトリの議題は出て、終了コードは 0。
反例: 1 つの議題が壊れているだけで、ps が理由を出して終わり、残ったサーバーを探せない。読めないリポジトリのディレクトリが 1 つあるだけで、どこで打っても ps が失敗する。
確かめ方: 議題のファイルが壊れたときは往復のテスト。リポジトリのディレクトリが読めないときは、人が権限を変えたディレクトリで再現して確かめる。

## 並び順

動いている議題を先に、止まった議題を後に並べる。それぞれの中は、更新した時刻が新しい順にする。更新した時刻が取れない議題は、それぞれの最後に置く。`--all-repos` でも、リポジトリごとにはまとめない。

成功条件: `-a` で、古い議題のサーバーが動いていれば、新しい止まった議題より上に出る。
反例: 動いているサーバーが、止まった議題の下に埋もれる。
確かめ方: 往復のテスト。

## 作らないもの

- 画面のヘッダーや LLM が会話に書く 1 行に、議題名を出すこと。URL や議題名がわからないときは ps で引ける。
- stop コマンドの拡張（リポジトリや PID の指定）。
- ps から選んでサーバーを止める対話の画面。
- ps が各サーバーに問い合わせること（LLM の状態や応答の有無を出すこと）。
- ps とは別の list コマンド。

## 見送った案

- ps と list を別のコマンドにする: 出す値の大半が重なり、似たコマンドが 2 つ並ぶ。
- どこで打っても全リポジトリを出す: いつも全リポジトリの情報が要るわけではない。
- `-a` を付けると範囲もカレントのリポジトリに変わる: 1 つの引数が 2 つの意味を持つ。
- stop をどこからでも使えるようにする: PID と kill で足り、応答しないサーバーも止められる。
- ps から選んで止める対話の画面: 対話の作りと端末でないときの動きが増える割に、kill で足りる。
- 出力をいつも JSON にする: 主な使い手は人。
- 各サーバーに HTTP で問い合わせて動いているかを決める: 待ち時間の上限と新しい状態が要る。応答しないサーバーも PID で kill できれば足りる。
- ファイルシステムの作成時刻から作った時刻を読む: ファイルシステムによっては取れず、コピーでずれる。
- 引数なしなら端末で議題を選んで再開する resume コマンド: 壁打ちを進めるのは LLM で、人がサーバーを立てても壁打ちは進まない。議題を探す手段は `ps -a` にした。

## 任せたこと

- text の表の列幅と、題名を切る長さ: text は見た目が変わってよい扱いで、どれを選んでも振る舞いは同じ。
