# 操作と知らせ

画面の図をどう動かすか、LLM から届いたものをどう知らせるか、画面がどの操作を約束するかを決める。
画面が何を見せるかは [画面](screen.md) に、届くものを渡すサーバーは [起動と往復と記録](server.md) にある。

用語は [CONTEXT.md](../../CONTEXT.md) に従う。

## 地図と完成図を動かす

地図と完成図は、拡大・縮小し、動かせる。ページのスクロールとぶつからないように、操作を次のように分ける。

- **ホイールだけ**: 図の上でも、ページをスクロールする。このとき図の上に「Ctrl＋ホイールで拡大」と短く出す（Mac では Ctrl の代わりに ⌘ と出す）。
- **Ctrl＋ホイール**: ポインタが図の上にあるときは、図を拡大・縮小し、ページは拡大しない。Mac では ⌘＋ホイールと Ctrl＋ホイールのどちらも図の拡大・縮小にする（トラックパッドのピンチは Ctrl＋ホイールとして届く）。図の外では、ブラウザのページ拡大がそのまま効く。
- **ピンチ**: タッチ画面でもトラックパッドでも、図を拡大・縮小する。
- **タッチで動かす**: 地図タブとダイアログで開いた図では、1 本指で図を動かす。ページの途中にある図（結果の中の完成図）では、1 本指はページのスクロールにし、図は 2 本指で動かす。

説明パーツのうち既存図は、拡大・縮小も移動もしない。図の上でも、ホイールとタッチはページをスクロールする。
新しいシーケンス図とフローチャートの領域内スクロールは [新しい図の表示](explanation-parts.md#新しい図の表示)、別表示の操作は [新しい説明図の拡大表示](#新しい説明図の拡大表示) に従う。

キーボードでは、拡大・縮小・全体のボタンと、点を選んで詳しい情報を開く操作を使う。図をドラッグで動かす操作は、キーボードでできなくてよい（[操作の約束](#操作の約束)）。

成功条件: 図の上でホイールだけを回すと、ページがスクロールし、案内が出る。図の上で Ctrl＋ホイールを回すと、図だけが拡大し、ページの拡大率は変わらない。結果の中の完成図を 1 本指でなぞると、ページがスクロールする。既存図パーツの上では、ホイールでも Ctrl＋ホイールでも図は変わらない。
反例: 図の上を通りかかったホイールが図に吸われ、ページをスクロールできない。図を拡大しようとして、ページごと拡大される。
確かめ方: 画面の自動テスト（ホイールだけでは図の拡大率が変わらないこと。Ctrl＋ホイールと ⌘＋ホイールで図の拡大率が変わり、その出来事の既定の動作が止められていること）。実物のブラウザでページが拡大されないこと、タッチとトラックパッドのピンチは、人が実物で確かめる。

## 新しい説明図の拡大表示

シーケンス図とフローチャートは、ボタンで別の拡大表示を開く。
閉じるボタンと Escape で閉じ、開いたボタンへフォーカスを戻す。
拡大表示では移動、拡大、縮小、リセットをキーボードで使える。
キーボードで移動する約束は新しい説明図に限り、地図と完成図の既存の約束は変えない。
通常のホイールでは図を拡大せず、Ctrl/⌘＋ホイールの扱いとピンチ、タッチ移動は [地図と完成図を動かす](#地図と完成図を動かす) のダイアログで開いた図に合わせる。
新しい図の拡大表示を加えても、既存図パーツには拡大操作を加えない。
画面を描き直したときのフォーカスと動きを減らす設定には [操作の約束](#操作の約束) を適用する。

成功条件: マウスなしで図を開き、移動、拡大、縮小、リセット、両方の閉じ方が使え、開いたボタンに戻る。通常ホイールで倍率が変わらず、修飾キー付きホイールでは図だけが拡大する。
反例: 開閉すると書きかけの回答欄へ勝手に移る。図の移動がドラッグでしかできない。既存図パーツにも拡大表示が付く。
確かめ方: キーボードの操作、倍率、閉じた後のフォーカス、既存図の不変を確かめる画面の自動テスト。実物のページ拡大率、タッチとピンチは人が実物で確認する。

## 届いたものの知らせ

LLM から次のラウンド（結果を含む）か質問の返事が届いたら、トーストで知らせる。知らせは、届いたものごとに次の表で決める。届いたものの種類が増えたら、表に 1 行足す。

| 届いたもの | 文言 | 移り先 |
|---|---|---|
| 次のラウンド | 第 n ラウンドが届きました | 今のラウンドの先頭 |
| 結果 | 結果が届きました | 今のラウンドの結果 |
| 質問の返事 | （問いの文の先頭 20 字。長ければ … で切る）への返事が届きました | そのカードの返事 |

トーストには「見る」を付け、押すと移り先へ移る。移るときは、移り先のタブとラウンドを選び、行やカードとその質問のやり取りを開き、省略されたやり取りがあれば全部出してから、届いたものを表示されている範囲に入れる。送ったあとに届いた返事は過去のラウンドに残る（[まとめて送る](screen.md#まとめて送る)）ので、その返事の「見る」は過去のラウンドへ移る。移った先からは、ヘッダーの「戻る」で元の場所へ戻れる（[移動と現在地](screen.md#移動と現在地)）。
届いたものがすでに見えているとき（今のタブで、届いたもの自体が表示されている範囲に描かれているとき）は、トーストを出さない。

ブラウザのタブが裏にある間に届いたものは、タブの題名の頭に件数を付けて示す（例: 「(2) 議題名」）。画面に戻ったら件数を消し、そのとき見えていない届いたものにだけトーストを出す。OS の通知は出さない。

ヘッダーの右側、LLM の状態の前に、届いたものの知らせのアイコンを置く（[ヘッダーと切替](screen.md#ヘッダーと切替)）。アイコンには、まだ見ていない届いたものの数をバッジで出す。押すと、最近届いたもの（10 件まで）の一覧を出し、ひとつ選ぶとそのトーストの「見る」と同じ先へ移る。一覧を開くとバッジは消える。トーストが消えたあとも、キーボードだけで届いたものへ行けるのは、このアイコンから。
届いたときに見えていたものと、トーストや一覧から移ったものは、見たものとしてバッジに数えない。一覧とバッジは、その画面を開いている間だけ持ち、保存しない。

トーストは 6 秒で消える。ポインタやフォーカスが乗っている間は消えない。重なったら縦に積む。4 つ目が出たら、ポインタもフォーカスも乗っていないもののうち、最も古いものを消す。全部に乗っているときは新しいものを積み、最も古いものはポインタとフォーカスが離れたときに消す。

成功条件: 見えていないカードに返事が届くと、トーストが出て、「見る」でそのカードの返事へ移り、「戻る」で元の場所へ戻れる。表示されている範囲にあるカードに返事が届いても、トーストは出ない。今のタブとは別のタブにあるカードに返事が届くと、トーストが出る。裏のタブに 2 つ届くと題名が「(2) 議題名」になり、戻ると消えてトーストが出る。トーストは 6 秒で消え、4 つ目が出ると、ポインタもフォーカスも乗っていないうち最も古いものが消える。「見る」で移ると、届いた返事そのものが表示されている範囲に出る（省略されたやり取りの中の返事でも）。知らせのアイコンには見ていない件数が出て、一覧を開くと消え、一覧から選ぶと「見る」と同じ先へ移る。届いたときに見えていたものは、バッジに数えられない。
反例: 次のラウンドが届いても、画面を見回さないと気づかない。トーストが消えたあと、キーボードだけでは届いたものへ行けない。トーストを読もうとポインタを乗せている間に消える。
確かめ方: 画面の自動テスト（時間は時計を差し替えて確かめる）。裏のタブでの題名の件数と、戻ったときのトーストは、人が実物のブラウザで確かめる。

## 操作の約束

画面は、次の 3 つを約束する。

- キーボードだけで、すべての操作ができる。地図と完成図をドラッグで動かす操作は除く（[地図と完成図を動かす](#地図と完成図を動かす)）。
- 画面を描き直しても、フォーカスしていた部品が描き直しのあとも残っていれば、フォーカスはそこに残る。その部品が消えたときにフォーカスがどこへ行くかは約束しない。
- 動きを減らす設定のときは、画面の動き（[待ちフッター](screen.md#待ちフッターの見た目) の 3 点や、カード内の返事待ちの点など）が止まる。待ちフッターは静止した点と文字を残し、動きがなくても待つ対象が分かる。

読み上げの細部とハイコントラスト表示は約束しない。

成功条件: マウスを使わずに、答えを選んで判子を押し、質問し、見直し、送れる。質問の返事が届いて画面が描き直されても、書きかけの欄からフォーカスが外れない。動きを減らす設定にすると、待ちフッターとカード内の点は静止し、待ちフッターの文字は残る。
反例: 返事が届くたびに、フォーカスがページの先頭へ飛ぶ。判子がマウスでしか押せない。動きを減らす設定でもフッターが明滅する。動きを止めると待つ対象の表示も消える。
確かめ方: 画面の自動テスト（主な操作をキーボードだけでたどる、描き直しの前後のフォーカス、送信後に OS の動きを減らす設定を反映し、点の動きと文字の表示を確かめる）。すべての操作がキーボードでそろっているかは、人が実物で確かめる。

## 作らないもの

- 読み上げの細部とハイコントラスト表示の約束（[操作の約束](#操作の約束)）。
- 地図と完成図を矢印キーで動かす操作（[地図と完成図を動かす](#地図と完成図を動かす)）。
- OS の通知。届いたものは、画面のトーストとタブの題名で知らせる（[届いたものの知らせ](#届いたものの知らせ)）。

## 見送った案

- 次のラウンドだけを知らせる: 見えていないカードの返事に気づけない。
- 知らせるだけで、届いたものへ移らない: 自分でタブやカードを探すことになる。
- OS の通知も出す: 許可の手間と、通知が多すぎる心配がある。
- 最新のトーストへ跳ぶキー（Alt+N など）を設ける: 覚える必要があり、ブラウザや OS のキーとぶつかりうる。
- 知らせのアイコンの代わりに「届いたもの（n）」の文字のボタンを置く: ヘッダーの幅を取る。
- 届いたものの一覧とバッジを保存して、開き直しても残す: 状態データが大きくなる。
- 既存図パーツも、ページの途中にある図として動かせるようにする: 既存図の操作は変えない。新しい説明図は [拡大表示](#新しい説明図の拡大表示) を使う。

## 任せたこと

- 届いたものの種類（次のラウンド・結果・質問の返事）を、画面が前の中身との差から割り出すか、サーバーが種類を添えて送るか: どちらでも画面の振る舞いは変わらない。実装の計画で決める。
