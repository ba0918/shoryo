# 操作と知らせ

画面の図をどう動かすか、LLM から届いたものをどう知らせるか、画面がどの操作を約束するかを決める。
画面が何を見せるかは [画面](screen.md) に、届くものを渡すサーバーは [起動と往復と記録](server.md) にある。

用語は [CONTEXT.md](../../CONTEXT.md) に従う。

## 地図と完成図を動かす

地図と完成図は、拡大・縮小し、動かせる。ページのスクロールとぶつからないように、操作を次のように分ける。

- **ホイールだけ**: 図の上でも、ページをスクロールする。このとき図の上に「Ctrl＋ホイールで拡大」と短く出す（Mac では Ctrl の代わりに ⌘ と出す）。
- **Ctrl＋ホイール**: ポインタが図の上にあるときは、図を拡大・縮小し、ページは拡大しない。Mac では ⌘＋ホイールと Ctrl＋ホイールのどちらも図の拡大・縮小にする（トラックパッドのピンチは Ctrl＋ホイールとして届く）。図の外では、ブラウザのページ拡大がそのまま効く。
- **ピンチ**: タッチ画面でもトラックパッドでも、図を拡大・縮小する。
- **タッチで動かす**: 地図タブとダイアログで開いた図では、1 本指で図を動かす。ページの途中にある図（結果の中の完成図）では、1 本指はページのスクロールにし、図は 2 本指で動かす。

説明パーツのうち既存図は、拡大・縮小も移動もしない。図の上でも、ホイールとタッチはページをスクロールする。
新しいシーケンス図とフローチャートの枠は [新しい図の表示](explanation-parts.md#新しい図の表示)、本文内の操作は [新しい説明図の本文内操作](#新しい説明図の本文内操作)、別表示の操作は [新しい説明図の拡大表示](#新しい説明図の拡大表示) に従う。
地図と完成図の操作部分の見た目と、操作中の文字選択の抑制は [図の操作部分](#図の操作部分) に従い、初期表示、移動、拡大縮小の刻み幅と全体表示の挙動は保つ。

キーボードでは、拡大・縮小・全体のボタンと、点を選んで詳しい情報を開く操作を使う。図をドラッグで動かす操作は、キーボードでできなくてよい（[操作の約束](#操作の約束)）。

成功条件: 図の上でホイールだけを回すと、ページがスクロールし、案内が出る。図の上で Ctrl＋ホイールを回すと、図だけが拡大し、ページの拡大率は変わらない。結果の中の完成図を 1 本指でなぞると、ページがスクロールする。既存図パーツの上では、ホイールでも Ctrl＋ホイールでも図は変わらない。
反例: 図の上を通りかかったホイールが図に吸われ、ページをスクロールできない。図を拡大しようとして、ページごと拡大される。
確かめ方: 画面の自動テスト（ホイールだけでは図の拡大率が変わらないこと。Ctrl＋ホイールと ⌘＋ホイールで図の拡大率が変わり、その出来事の既定の動作が止められていること）。実物のブラウザでページが拡大されないこと、タッチとトラックパッドのピンチは、人が実物で確かめる。

## 新しい説明図の本文内操作

本文内のシーケンス図とフローチャートは、通常ホイールではページを読み進め、意図したマウスのドラッグでは図の表示位置を動かす。
図には通常ホイールを消費するネイティブな内部スクロールを設けない。
Ctrl または Meta（Mac では ⌘）を押したホイールでは、ポインター位置を基準に図だけを拡大縮小する。
図の外やコードの操作には介入せず、図の上にポインターがあるだけでは移動も拡大縮小もしない。

本文内のタッチ操作では、図の上でも 1 本指はページの読み進めに使い、2 本指で図を移動し、ピンチで図を拡大縮小する。
操作方法が分かる案内を出す。
本文内でも図の領域と操作部品へフォーカスでき、キーボードから移動と拡大縮小を使い、枠の外の内容までたどれる。
図にフォーカスしたときの矢印キーと +、− は、新しい拡大表示の既存の移動と拡大縮小の操作に合わせ、入力欄や図の外のキーを奪わない。
新しい説明図の領域にフォーカスして 0 キーを押すと、本文内でも拡大表示でも、その表示領域に図全体を収める縮尺に合わせ、中央に置く。
0 キーは自然な 100％へのリセットや直前の位置と縮尺の復元にはせず、「全体」と同じ役割として案内する。
0 キーでフォーカスを移動せず、入力欄や図の外ではこの操作を行わない。
地図と完成図の既存のショートカットは変えない。
図の枠と初期縮尺は [新しい図の表示](explanation-parts.md#新しい図の表示)、文字選択は [図の操作部分](#図の操作部分) に従う。

成功条件: 大きい図の上で通常ホイールを回してもページを読み進められ、図の内部スクロール位置や縮尺は変わらない。ドラッグ、キーボード、2 本指で枠の外の内容に到達でき、修飾キー付きホイールではポインター下の図の位置を基準に拡大縮小する。1 本指ではページを読み進められる。本文内と拡大表示の図を移動して拡大したあと、図にフォーカスして 0 を押すと、それぞれの表示領域に全体が中央配置で収まり、フォーカスは残る。入力欄や図の外での 0 と地図や完成図のショートカットは変わらない。
反例: スクロールバーだけを隠してホイールを内部で消費する。本文内ではマウスでしか図を動かせない。コード上の Ctrl＋ホイールまで図の操作として奪う。1 本指で図が動いてページを読めなくなる。0 で自然な 100％へ戻すだけにして図の端を隠す。回答欄への 0 の入力を奪う。地図のキー操作まで変更する。
確かめ方: 画面の自動テストでページ位置、図の位置と縮尺、ポインター基準、図の外とコードへの非介入、キーボード操作を確かめる。本文内と拡大表示の両方で、移動と拡大後の 0 による全体の収まりと中央位置、フォーカスの維持、入力欄と図の外の 0 への非介入、地図と完成図の既存のキー操作の不変を確かめる。実物のブラウザでページ拡大との分離を確認し、1 本指のページ移動、2 本指の移動とピンチの両立は人がタッチ実機で確かめる。合意や合成イベントだけで実機確認済みとは扱わない。

## 新しい説明図の拡大表示

シーケンス図とフローチャートは、[右上の拡大アイコン](explanation-parts.md#新しい図の表示) で別の拡大表示を開く。
開いた直後は、同じ図の全体を表示領域に収める縮尺にし、中央に置く。
「全体」操作も全体を収めて中央に置き、大きい図では文字が小さくなることを許容する。
文字や内容は省略せず、利用者が手動で読みやすい縮尺に拡大できるようにする。
図の表示領域は、まとまったヘッダーと操作部分の残りの高さを使う主領域とし、固定した画面高さ比率の図枠とダイアログ内部スクロールを重ねない。
題名、立場、現在の倍率は見える状態に保ち、操作の配置は [図の操作部分](#図の操作部分) に従う。

右上の閉じるアイコン、Escape、背景部分のクリックで閉じ、開いたアイコンへフォーカスを戻す。
開くと図の領域にフォーカスを置き、Tab の移動はダイアログ内に保つ。
拡大表示では移動、拡大、縮小、全体表示をキーボードで使える。
矢印キーと +、− による既存の移動と拡大縮小は維持し、入力欄や図の外のキーを奪わない。
0 キーの全体表示と、そのフォーカス範囲は [本文内と拡大表示に共通するキー操作](#新しい説明図の本文内操作) に従う。
キーボードで移動する約束は新しい説明図に限り、地図と完成図の既存の約束は変えない。
通常のホイールでは図を拡大せず、Ctrl/⌘＋ホイールの扱いとピンチ、タッチ移動は [地図と完成図を動かす](#地図と完成図を動かす) のダイアログで開いた図に合わせる。
新しい図の拡大表示を加えても、既存図パーツには拡大操作を加えない。
画面を描き直したときのフォーカスと動きを減らす設定には [操作の約束](#操作の約束) を適用する。
図を開いた場所は題名ではなく、ラウンド、問い、説明の場所、パーツの位置で識別し、同じ題名があっても描き直し後のフォーカスを混同しない。
移動と縮尺の状態は表示部品に属し、説明データや議題の保存形式には加えない。
同時に開くダイアログは 1 つとし、既存のダイアログを明示的に置き換える規則は変えない。
開いたアイコンが消えたときは、新しい戻り先を約束しない。

成功条件: 横長や縦長の図を開くと全体が中央に収まり、拡大後も同じ内容を読める。マウスなしで開き、移動、拡大、縮小、全体表示、閉じるアイコンと Escape が使え、開いたアイコンに戻る。背景からも閉じられ、描き直し後や同名の図でも戻り先を混同しない。通常ホイールで倍率が変わらず、修飾キー付きホイールでは図だけがポインター位置を基準に拡大する。
反例: 常に自然な 100％で開く。「全体」が自然な縮尺へ戻すだけで図の端を隠す。開閉すると書きかけの回答欄へ勝手に移る。図の移動がドラッグでしかできない。固定高さの図枠の周囲に余白や二重のスクロールを作る。既存図パーツにも拡大表示が付く。
確かめ方: 画面の自動テストで全体の収まりと中央位置、内容の保持、主領域の寸法、キーボード操作、Tab の範囲、各閉じ方と描き直し後のフォーカス、既存図の不変を確かめる。実物のページ拡大率、タッチとピンチは人が実物で確認する。両テーマと広い画面、狭い画面で図が主領域として使われ、ヘッダーと操作がまとまっているかも人が確認する。

## 図の操作部分

新しい説明図の拡大表示、地図、完成図は、同じ役割の操作を同じアイコンと視覚的なまとまりで出す。
縮小、現在の倍率、全体、拡大をひとまとまりにし、拡大表示の閉じるアイコンは右上に分ける。
新しい説明図の移動操作はコンパクトなメニューにまとめ、キーボードでも開閉して方向を選べるようにする。
地図と完成図には移動メニューや新しいキーバインドを追加せず、既存の操作だけを共通の見た目に揃える。
アイコンには操作名、ツールチップ、見分けられるフォーカス表示を付け、現在の倍率は文字で読めるようにする。
説明を読むための操作は送信後や過去ラウンドでも使え、選択肢の回答操作から独立させ、操作しても回答や判子を変えない。
自然な 100％に合わせる専用ボタン、全体表示の直前の位置と縮尺へ戻す専用操作、初期表示を比較するセレクトは置かない。

新しい説明図の本文内と拡大表示、および地図と完成図では、図の移動中にラベルが文字選択されるのを防ぐ。
図の領域に限って選択を抑制し、コードの文字選択と地図の点を選んで詳しい情報を読む既存操作は保つ。
色、余白、アイコンの輪郭は具体的な仕様値として固定せず、承認した枠と操作のまとまりを実物で判断する。

成功条件: 説明図から地図や完成図に移っても、縮小、倍率、全体、拡大の役割を同じまとまりから見つけられる。新しい説明図の移動メニューをキーボードで使え、ラベル上からドラッグしても文字は選択されない。送信後や過去ラウンドでも図を読め、回答と判子は変わらない。コードは選択でき、地図の既存の情報表示と初期表示、移動、拡大縮小は変わらない。
反例: 平坦なボタン列に閉じると移動と倍率をばらばらに並べる。100％ボタンや比較用セレクトを残す。見た目を揃えるため地図にも矢印キー移動を足す。ページ全体の文字選択を禁止する。
確かめ方: 画面の自動テストで操作名、ツールチップ、倍率、メニューのキーボード操作、ドラッグ後の選択、コードの選択、送信後と過去ラウンドの操作、回答と判子の不変、地図と完成図の既存挙動の不変を確認する。本人が両テーマと広い画面、狭い画面でコード枠から説明図の拡大表示、地図、完成図へ順に移り、枠とヘッダー、同じ役割のアイコンとまとまりを探し直さず使えるかを確認する。モックとのピクセル単位の一致や仕様文の完全一致を自動テストの合格条件にはしない。

## 届いたものの知らせ

LLM から次のラウンド（結果を含む）か質問の返事が届いたら、トーストで知らせる。知らせは、届いたものごとに次の表で決める。届いたものの種類が増えたら、表に 1 行足す。

| 届いたもの | 文言 | 移り先 |
|---|---|---|
| 次のラウンド | 第 n ラウンドが届きました | 今のラウンドの先頭 |
| 結果 | 結果が届きました | 今のラウンドの結果 |
| 質問の返事 | （問いの文の先頭 20 字。長ければ … で切る）への返事が届きました | そのカードの返事 |

トーストには「見る」を付け、押すと移り先へ移る。移るときは、移り先のタブとラウンドを選び、行やカードとその質問のやり取りを開き、省略されたやり取りがあれば全部出してから、届いたものを表示されている範囲に入れる。送ったあとに届いた返事は過去のラウンドに残る（[まとめて送る](screen.md#まとめて送る)）ので、その返事の「見る」は過去のラウンドへ移る。移った先からは、ヘッダーの「戻る」で元の場所へ戻れる（[移動と現在地](screen.md#移動と現在地)）。
届いたものがすでに見えているとき（今のタブで、届いたもの自体が表示されている範囲に描かれているとき）は、トーストを出さない。

ブラウザのタブが裏にある間に届いたものは、タブの題名の頭に件数を付けて示す（例: 「(2) 議題名」）。画面に戻ったら件数を消し、そのとき見えていない届いたものにだけトーストを出す。OS の通知は出さない。

ヘッダーの右側、LLM の状態の前に、届いたものの知らせのアイコンを置く（[ヘッダーと切替](screen.md#ヘッダーと切替)）。アイコンには、まだ見ていない届いたものの数をバッジで出す。押すと、最近届いたもの（10 件まで）の一覧を出し、ひとつ選ぶとそのトーストの「見る」と同じ先へ移る。一覧を開くとバッジは消える。トーストが消えたあとも、キーボードだけで届いたものへ行けるのは、このアイコンから。
届いたときに見えていたものと、トーストや一覧から移ったものは、見たものとしてバッジに数えない。一覧とバッジは、その画面を開いている間だけ持ち、保存しない。

トーストは 6 秒で消える。ポインタやフォーカスが乗っている間は消えない。重なったら縦に積む。4 つ目が出たら、ポインタもフォーカスも乗っていないもののうち、最も古いものを消す。全部に乗っているときは新しいものを積み、最も古いものはポインタとフォーカスが離れたときに消す。

成功条件: 見えていないカードに返事が届くと、トーストが出て、「見る」でそのカードの返事へ移り、「戻る」で元の場所へ戻れる。表示されている範囲にあるカードに返事が届いても、トーストは出ない。今のタブとは別のタブにあるカードに返事が届くと、トーストが出る。裏のタブに 2 つ届くと題名が「(2) 議題名」になり、戻ると消えてトーストが出る。トーストは 6 秒で消え、4 つ目が出ると、ポインタもフォーカスも乗っていないうち最も古いものが消える。「見る」で移ると、届いた返事そのものが表示されている範囲に出る（省略されたやり取りの中の返事でも）。知らせのアイコンには見ていない件数が出て、一覧を開くと消え、一覧から選ぶと「見る」と同じ先へ移る。届いたときに見えていたものは、バッジに数えられない。
反例: 次のラウンドが届いても、画面を見回さないと気づかない。トーストが消えたあと、キーボードだけでは届いたものへ行けない。トーストを読もうとポインタを乗せている間に消える。
確かめ方: 画面の自動テスト（時間は時計を差し替えて確かめる）。裏のタブでの題名の件数と、戻ったときのトーストは、人が実物のブラウザで確かめる。

## 操作の約束

画面は、次の 3 つを約束する。

- キーボードだけで、すべての操作ができる。地図と完成図をドラッグで動かす操作は除く（[地図と完成図を動かす](#地図と完成図を動かす)）。
- 画面を描き直しても、フォーカスしていた部品が描き直しのあとも残っていれば、フォーカスはそこに残る。その部品が消えたときにフォーカスがどこへ行くかは約束しない。
- 動きを減らす設定のときは、画面の動き（[待ちフッター](screen.md#待ちフッターの見た目) の 3 点や、カード内の返事待ちの点など）が止まる。待ちフッターは静止した点と文字を残し、動きがなくても待つ対象が分かる。

読み上げの細部とハイコントラスト表示は約束しない。

成功条件: マウスを使わずに、答えを選んで判子を押し、質問し、見直し、送れる。質問の返事が届いて画面が描き直されても、書きかけの欄からフォーカスが外れない。動きを減らす設定にすると、待ちフッターとカード内の点は静止し、待ちフッターの文字は残る。
反例: 返事が届くたびに、フォーカスがページの先頭へ飛ぶ。判子がマウスでしか押せない。動きを減らす設定でもフッターが明滅する。動きを止めると待つ対象の表示も消える。
確かめ方: 画面の自動テスト（主な操作をキーボードだけでたどる、描き直しの前後のフォーカス、送信後に OS の動きを減らす設定を反映し、点の動きと文字の表示を確かめる）。すべての操作がキーボードでそろっているかは、人が実物で確かめる。

## 作らないもの

- 読み上げの細部とハイコントラスト表示の約束（[操作の約束](#操作の約束)）。
- 地図と完成図を矢印キーで動かす操作（[地図と完成図を動かす](#地図と完成図を動かす)）。
- OS の通知。届いたものは、画面のトーストとタブの題名で知らせる（[届いたものの知らせ](#届いたものの知らせ)）。
- 100％専用ボタン、全体表示の直前の状態へ戻す専用操作、比較用の初期表示セレクト（[図の操作部分](#図の操作部分)）。
- 既存図パーツへの移動や拡大縮小の追加、地図と完成図への新しい移動メニューやキーバインドの追加。

## 見送った案

- 次のラウンドだけを知らせる: 見えていないカードの返事に気づけない。
- 知らせるだけで、届いたものへ移らない: 自分でタブやカードを探すことになる。
- OS の通知も出す: 許可の手間と、通知が多すぎる心配がある。
- 最新のトーストへ跳ぶキー（Alt+N など）を設ける: 覚える必要があり、ブラウザや OS のキーとぶつかりうる。
- 知らせのアイコンの代わりに「届いたもの（n）」の文字のボタンを置く: ヘッダーの幅を取る。
- 届いたものの一覧とバッジを保存して、開き直しても残す: 状態データが大きくなる。
- 既存図パーツも、ページの途中にある図として動かせるようにする: 既存図の操作は変えない。新しい説明図は [拡大表示](#新しい説明図の拡大表示) を使う。
- 新しい説明図の拡大表示を自然な 100％で開く: 初めに全体を収めて中央に置き、必要に応じて拡大する方式を採る。
- 100％に合わせる専用ボタンを残す: 全体表示と手動の拡大縮小に操作を絞る。
- 本文内の新しい説明図で 1 本指を図の移動に使う: 図の上からもページを読み進められるようにする。
- 新しい説明図の 0 キーを自然な 100％への操作として残す: 本文内と拡大表示で「全体」と同じ役割に揃える。
