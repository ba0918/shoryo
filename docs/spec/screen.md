# 画面

shoryo の画面では、壁打ちの問いを読み、LLM に質問し、答える。
CLI の対話に問いが大量に流れてくる状態をなくし、問いのつながりと最終形を頭の中で組み立てなくて済むようにする。
画面が描くデータと、LLM との往復は [起動と往復と記録](server.md) にある。
問いや説明の中身を LLM がどう書くかは [shoryo skill](skill.md) にある。
図の動かし方、届いたものの知らせ、キーボードなどの操作の約束は [操作と知らせ](interaction.md) にある。
詳細説明と返事に使う種類付きの列と、その表示規則は [説明パーツ](explanation-parts.md) にある。

用語は [CONTEXT.md](../../CONTEXT.md) に従う。

## 画面の構成

画面には次の 4 つのタブがある。

- 今のラウンド
- 過去のラウンド
- 地図
- 決まったこと

画面の上部には、議題の題名を出す。そもそもの議題（本人の言葉）は、開くと読める。
完成図は、どのタブからでも開ける。

成功条件: 4 つのタブがある。
反例: タブを移らないと完成図を開けない。
確かめ方: 画面の自動テスト。

## ヘッダーと切替

画面の一番上に、薄いヘッダーを固定する。左に「戻る」と議題の題名を、右に届いたものの知らせのアイコン（[届いたものの知らせ](interaction.md#届いたものの知らせ)）、LLM の状態（[表示条件](#llm-の状態)に当たるときだけ）、設定ファイルを読めないことの知らせ（読めないときだけ。[切替は設定に残る](#切替は設定に残る)）、テーマのアイコン、言語の切替（en | ja）をこの順に並べる。
「戻る」は、戻れる先があるときだけ出す（[移動と現在地](#移動と現在地)）。
スクロールしても、ヘッダーは画面の上に残る。

成功条件: 左から「戻る」（戻れる先があるときだけ）と題名、右側に届いたものの知らせのアイコン、LLM の状態（表示条件に当たるときだけ）、設定ファイルを読めないことの知らせ（読めないときだけ）、テーマ、言語の順で並ぶ。ページの下までスクロールしても、ヘッダーと「戻る」が見えている。
反例: 「戻る」がページの途中にあり、戻るたびにスクロールが要る。戻れる先がないのに「戻る」が出る。
確かめ方: 画面の自動テスト。

### LLM の状態

ヘッダーの状態表示は、[現在の操作待ち](server.md#llm-の状態)が確認できるときだけ出す。
点と短い文字「操作待ち」を一緒に出し、点は動かさない。
それ以外は状態表示を出さず、「状態不明」「作業中」「応答なし」や最後の通信からの経過時間で埋めない。
送信後に何を待っているかは [送ったあとの知らせ](#送ったあとの知らせ) で伝える。

成功条件: 操作待ちが確認できる間だけ、静止した点と「操作待ち」が出る。確認できなくなると表示が消え、議題を終えたあとも出ない。
反例: 点の色だけで操作待ちを示す。wait が戻ると作業中を出す。正常な長い処理の間に状態不明を出す。
確かめ方: 画面の自動テスト（エージェントが wait を開始し、出来事または上限で戻り、議題を終える流れを入力する）。

### 言語

画面に最初から書いてある文言（ボタン、見出し、タブ名など）を、英語と日本語で切り替えられる。
言語を設定していないときは英語で出す。
日本語の文言には、用語集（[CONTEXT.md](../../CONTEXT.md)）の言葉を使う。
問い・選択肢・説明など、LLM が書く中身は、切り替えても書かれた言語のまま出す。

成功条件: 切替で ja を選ぶと、固定の文言が日本語になり、LLM が書いた中身は変わらない。設定がないときは英語で出る。
反例: 切り替えると問いの文まで訳される。日本語の画面で、用語集と違う言葉（「スキップ」「チャット」など）が出る。
確かめ方: 画面の自動テスト。

### テーマ

ライトとダークを切り替えられる。テーマの値は「OS に合わせる」「ライト」「ダーク」の 3 つで、設定していないときは OS に合わせる。
ヘッダーのアイコンは、押すたびに「ライト → ダーク → OS に合わせる」の順に回る。今どれかはアイコンでわかる。

成功条件: アイコンを 3 回押すと、ライト・ダーク・OS に合わせるを順にたどって元に戻る。設定がないときは OS の明るさの設定に従う。
反例: ダークにすると読めない色の組み合わせが出る。
確かめ方: 画面の自動テスト。

### 切替は設定に残る

言語とテーマを画面で切り替えると、ユーザーごとの設定ファイルに書き込む（[設定ファイル](server.md#設定ファイル)）。どの議題を開いても、同じ言語とテーマで出る。

別の議題ですでに開いている画面には、読み込み直したときに反映する。
設定ファイルが読めないときは、画面の切替はその画面を開いている間だけ効き、ファイルには書かない。ヘッダーの右側、テーマのアイコンのすぐ前に、設定ファイルを読めないことを出す（[ヘッダーと切替](#ヘッダーと切替)）。

成功条件: ある議題の画面で ja とダークに切り替えたあと、別の議題を起動して開くと、ja とダークで出る。
反例: 議題ごとやブラウザごとに切替がやり直しになる。
確かめ方: 往復のテスト。

## 今のラウンド

### 並び

今のラウンドは、上から次の順に並ぶ。

1. 直したこと（レビューのラウンドのときだけ。[直したこと](#直したこと)）
2. 人が決める問いのカード
3. 仮決めの一覧
4. 「まとめて送る」（未送信のとき。送信後は [送ったあとの知らせ](#送ったあとの知らせ)）

成功条件: 人が決める問いと仮決めが、混ざらずにこの順で出る。
反例: 仮決めの問いが、人が決める問いと同じ形のカードで並ぶ。
確かめ方: 画面の自動テスト。

### たたんだカード

カードは最初、たたんだ状態で出る。たたんだカードには次のものを出す。

- 問いの文と、「人が決める」の印
- なぜ今決めるか（1 行）
- 前提の行（[前提の行](#前提の行)）
- 選択肢と、推奨の印
- 選んでいる答えの結果（[この答えだと](#この答えだと)）
- 判子（[判子](#判子)）

カードを開くと、次のものも出る。

- 前提になっている決まったことの全文
- 前提知識
- 選択肢ごとの説明

前提知識と選択肢ごとの詳細説明は、[説明パーツ](explanation-parts.md#対象と読み順) の列を指定順に出す。
問いの文と「この答えだと」は短い文章のままにする。

成功条件: 開く前に上のものが見え、開くと残りの 3 つが加わる。前提知識と選択肢の詳細説明がパーツの指定順で出て、問いと選択結果は文章のままである。
反例: 開かないと推奨がどれかわからない。開く前から前提知識の全文が出ていて、カードが長い。
確かめ方: 画面の自動テスト。

### 答え欄の初期値

答え欄には、最初から推奨の選択肢が選ばれている。補足を書く欄もある。

成功条件: 選択肢を変えずに判子を押して送ると、その問いは推奨で答えたことになる。
反例: 人が決める問いだけ、何も選ばれていない。
確かめ方: 画面の自動テスト。

### この答えだと

選んでいる選択肢の結果を、選択肢の下に出す。選択肢を変えると、その場で中身が変わる。
結果の文は、LLM が選択肢ごとに書く。

成功条件: 選択肢を切り替えると、結果の文が切り替えた選択肢のものに変わる。
反例: 送るまで結果が見えない。
確かめ方: 画面の自動テスト。

### 前提の行

カードには、その問いが前提にしている決まったことを、短い名前でつないで出す。
問いが直接前提にしている決まったことから始めて、それを決めた問いの前提へさかのぼり、3 つまでつなぐ。
さかのぼった先の問いに前提が複数あるときは、記録に書かれた順で最初の前提をたどる。
直接の前提が複数あるときは、前提ごとの並びを区切って横に並べる。
例: 「まとめて送る・質問できる ← まず UI を確定 ← 成功は体感で判断 ／ 見やすさが最重要」

名前をクリックすると、その決まったことの全文と、どの問いで決まったかが出る。
見直し中の決まったことには、見直し中の印を付ける。

成功条件: 番号ではなく短い名前で並び、クリックで全文と出どころの問いが出る。
反例: 「A12 ← A11」のように番号だけが並ぶ。前提が木の形で広がる。
確かめ方: 画面の自動テスト。

### 仮決めの一覧

仮決めの問いは、一覧にまとめて出す。各行には、問い、推奨が入った選択、選択の結果、判子を出す。
仮決めの行は、LLM が代決した判子が押された状態で出る（[判子](#判子)）。人は一覧を後閲し、気になる行だけ差し戻す。
行を開くとカードになり、質問、先送りのラベル、補足が使える。

人は、どの問いも「人が決める」と「仮決め」の間で入れ替えられる。入れ替えはその場で反映され、問いはカードと一覧の間を移る。

成功条件: 仮決めの選択を一覧のまま変えられる。行を開くと質問できる。入れ替えると、カードと一覧の間を移る。
反例: 仮決めは一覧の中で変えられない。人が仕分けを直せない。
確かめ方: 画面の自動テスト。

### 質問

カードの下で、その問いについて LLM に質問できる。質問のしかたは 2 つある。

- 質問の欄に書いて送る。決まった言い方のボタン（Explain more、Simplify with a diagram、What does the recommendation mean? など）を押すと、その文が欄に入る。押しただけでは送らない。送るのは送信ボタンか Enter。
- 返事をひとつ選び、「この返事に続けて質問」を押して、その続きとして聞く

質問を送ると、LLM が返事を書いている間、そのカードに順に弾む 3 つの点を出し、読み上げには返事を書いていることを伝える。返事が届いたら、そこに出る。
返事を待っている間も、ほかのカードを読んだり、答えたり、質問したりできる。
送る前なら、同じ問いに何度でも質問できる。

やり取りは、見出し「LLM への質問（件数）」で開け閉めする。質問がある問いは、最初から開いた状態で出す。
開くと、やり取りを聞いた順に 1 本の流れで出す。返事に続けて聞いたものも入れ子にせず、その流れに並べ、どの返事への続きかを短い引用で示す（[返事への続きの引用](#返事への続きの引用)）。
やり取りが 5 件を超えたら、最初の 1 件と最近の 2 件だけを出し、間は省略した件数を示して畳む。押すと全部出る。

返事は [説明パーツ](explanation-parts.md#対象と読み順) の列を指定順に出す。

成功条件: 2 つの問いに続けて質問し、どちらの返事も届く前にほかのカードを操作できる。返事を書いている間は 3 つの点が出て、返事が届くと返事に置き換わる。返事はそれぞれのカードの下に出る。決まった言い方のボタンを押しても、送信ボタンを押すまで LLM に届かない。続きとして聞いたものは、引用付きで時系列の位置に出る。
反例: 返事が届くまで画面を操作できない。返事が画面の横の別の欄に出る。ボタンを押し間違えると、そのまま届く。続きとして聞いたものが字下げされて入れ子になる。
確かめ方: 画面の自動テスト（LLM の返事は往復のテスト用の入力で代える）。読み上げに返事を書いていることが伝わるかは、人が読み上げソフトで確かめる。

### 返事への続きの引用

引用は返事の最初のパーツから作る。
文章なら冒頭の短い引用、図なら題名、コードなら任意の題名か言語と立場を短く示す。
コードや図の元データ全文は引用欄に出さない。
図やコードから始まる返事に導入文を必須にしない。
続きの関係は表示の引用ではなく、従来どおり返事の識別子で保持する（[状態データ](server.md#状態データ)）。

成功条件: 文章、図、題名付きコード、題名なしコードから始まる返事をそれぞれ識別でき、同じ題名の返事が複数あっても正しい返事へ続く。
反例: コード本文全文が引用される。題名を返事の識別子代わりに使う。文章を先頭に追加しないと続けて質問できない。
確かめ方: 画面と往復の自動テストで、各先頭種類の引用と続きの識別子を確かめる。文面の完全一致ではなく、元の返事を識別する情報を確かめる。

### 先送りのラベル

どのカードでも、「次のラウンドで聞き直して」のスイッチを入れられる。選択肢とは別のスイッチ。
入れたまま送ると、選んでいる選択肢は答えとして扱わず、その問いは決まらずに残る。
LLM は次のラウンドで、聞き方を変えて出し直す（[聞き直し](skill.md#先送りされた問いの聞き直し)）。

成功条件: 先送りを入れて送った問いは、決まったことにならない。
反例: 先送りを入れても推奨で決まる。
確かめ方: 往復のテスト。

### 判子

問いには 1 問に 1 つ、判子がある。判子は、その問いの答え（先送りを含む）を確かめたことを示す。読んだ証明ではなく、1 問ずつ手を止める場面を作り、押し忘れをなくすためのもの。

- **人が決める問い**: 判子なしで出る。本人が押す。
- **仮決め**: LLM が代決した判子が押された状態で出る。本人は後閲し、気になる行は差し戻して判子を外す。差し戻した行は、その行で選び直して本人が押す。
- 判子を押したあとで選択肢や先送りのラベルを変えたら、判子は外れる。押し直す。補足を書き換えても、判子は外れない。
- 押した判子は、もう一度押すと外れる。仮決めの代決の判子を外すこと、または一覧で選択肢を変えることが差し戻しになる。どちらの場合も、その行は本人が押し直す。
- 先送りのラベルを入れた問いにも、判子が要る。
- 仮決めと人が決める問いを入れ替えたら、移った先の初めの状態になる（人が決める問いは判子なし、仮決めは代決の判子付き）。

本人が押した判子には、押した日付を「10/8」のように月/日で出す。カーソルを合わせたときとフォーカスしたときは、年と時刻まで出す。もう押せない判子（過去のラウンドと、送ったあとの判子）では、タップしても年と時刻を出す。今のラウンドの判子をタップすると、これまでどおり押す・外すになる。時刻は、ブラウザの地域の時刻で出す（記録のしかたは [状態データ](server.md#状態データ)）。代決の判子には、そのラウンドを送った日の日付を出し、カーソルを合わせたとき、フォーカスしたとき、タップしたときは、送った年と時刻まで出す。まだ送っていない代決の判子には、日付を出さない。

すべての問いに判子がそろうまで、「まとめて送る」は押せない。「まとめて送る」の横には判子のない問いの数を出し、押すとその問いへ移る。

成功条件: 人が決める問いに判子のない問いが 1 つでもあると送れず、全部押すと送れる。仮決めは差し戻さなければ判子付きのまま送れる。判子を押したあとに選択肢を変えると判子が外れる。判子を押すと、押した日の月/日が判子に出て、カーソルを合わせても、フォーカスしても、年と時刻が出る。外して押し直すと、押し直した時刻になる。送る前の代決の判子には日付がなく、送ると送った日の日付が出て、カーソルを合わせると送った年と時刻が出る。
反例: 判子のない問いを残したまま送れる。選択肢を変えても判子が残る。今のラウンドの判子をタップしても押せず、時刻が出るだけになる。
確かめ方: 画面の自動テスト（日付は、画面の時計と地域を差し替えて確かめる。サーバーの時計は差し替えない）。もう押せない判子をタップすると年と時刻が出ることは、人が実物で確かめる。

### まとめて送る

「まとめて送る」で、今のラウンドの答えを全部まとめて LLM に送る。押せるのは、すべての問いに判子がそろってから（[判子](#判子)）。
答え欄の初期値（推奨）のまま判子を押して送った問いも、答えたことになる。

送ったあとは、次のラウンドが届くまで、今のラウンドの答え・質問・仕分けの入れ替えは使えない。「見直す」も、どのタブでも押せない（[見直す](#見直す)）。
送る前に返事待ちだった質問は、あとから返事が届けば、そのラウンドの記録に残る。

成功条件: 送ると、全部の問いの答えが 1 回で LLM に届く。送ったあとに遅れて届いた返事が、過去のラウンドで見られる。
反例: 問いごとに送る。送っていない仮決めが、決まったことになる。
確かめ方: 往復のテスト。

### 送ったあとの知らせ

[送信後の待ち](server.md#送信後の待ち) が成立している間は、画面下部に待ちフッターを出す。
待ちの成立、解除、開き直したときの復元と時間の基準は、その仕様に従う。
送信したことと待つ対象を、次のように文字で示す。

| 送ったもの | 伝える内容 |
|---|---|
| 問いのあるラウンドの答え | 回答を送りました。次のラウンド待ち |
| 結果からの見直し依頼 | 見直し依頼を送りました。次のラウンド待ち |
| この結果で進める | 結果を送りました。議題の終了待ち |

待ちフッターは、今のラウンドだけでなく、過去のラウンド、地図、決まったことのどのタブでも、最新の送信への待ちを示す。
過去のラウンドを見ているときは、待ちの対象のラウンド番号も添える。
今のラウンド上部の送信済み案内と、送信後に残る押せない送信ボタンは出さず、待ちフッターに集約する。
未送信のラウンドの送信操作と、[過去の結果の送信履歴](#過去のラウンド)は変えない。

時間による確認案内が必要になったら、待ち表示を残し、待つ対象がまだ届いていないこととエージェント側の画面を確認する案内を添える。
赤い警告やエラーにせず、停止や応答なしと断定せず、確認を強制する操作も追加しない。
待ち表示や動きは、LLM が実際に推論中、稼働中、仕様作成中であることや進捗率を示さない。
表の意味を保つ範囲で、短い案内の文面の細部は [任せたこと](#任せたこと) に従う。

成功条件: 3 種類の送信をそれぞれサーバーが受け付けると、対応する送信完了と待つ対象がフッターに出る。タブを移っても最新の待ちが残り、過去を見ているときは対象のラウンド番号が出る。今のラウンド上部の案内と押せない送信ボタンはなく、過去の結果にはどう送ったかが残る。確認案内が出ても、待つ対象は変わらない。
反例: 確認ダイアログを開いただけで送信完了と出る。この結果で進めたのに次のラウンド待ちと出る。見直し依頼を送っただけで見直し完了と出る。過去のラウンドへの待ちに見える。確認案内を停止の警告として出す。
確かめ方: 画面の自動テスト（実際の送信操作とサーバーの状態反映、タブ移動、過去の結果の閲覧、時間による案内を確かめる。文面の完全一致ではなく、送ったものと待つ対象の区別を確かめる）。

#### 待ちフッターの見た目

待ちフッターは、送信した場所が待つ段階へ変わったと分かる程度に目立たせつつ、控えめに強調する。
ライトテーマでは淡い青の背景に、左側に送信完了と短い待ち文言、右側に小さな 3 点の反復明滅を置く。
ダークテーマでは同程度の控えめな強調にし、狭い画面でも文字と待つ対象を読めるようにする。
動きを減らす設定での扱いは [操作の約束](interaction.md#操作の約束) に従う。

成功条件: 送信前後で待つ段階への切替が分かり、ライト、ダーク、狭い画面で文言が読める。小さな 3 点の動きを止めても、文字だけで何を待つか分かる。
反例: 大きな回転表示や強い点滅が実際の処理中に見える。ダークテーマや狭い画面で待つ対象が読めない。
確かめ方: 画面の自動テスト（両テーマと狭い表示幅で文字が欠けずに表示されることと、3 点の表示を確かめる）。控えめな強調の程度と待ちとしての分かりやすさは、人が実装後の画面で送信前後を見比べて確かめる。

### 結果

問いのないラウンドは、壁打ちが収束したことを表す。このときは問いのカードの代わりに「結果」を出す。

- 完成図（最後に描かれたもの）
- 決まったこと（本人が判子を押したものと、代決のまま送ったものを見分けて）
- 作らないもの、見送った案、未決、任せたこと

結果の見出しに添える案内は、今のラウンドの状態に合わせる。
未送信なら `壁打ちがまとまりました。完成図と決まったことを確かめて、気になるものがあれば「見直す」を押してください。` とする。
送信後は「結果を送りました。完成図と決まったことは引き続き確認できます。」、議題の終了後は「この議題は終了しました。完成図と決まったことを確認できます。」とする。
英語でも同じ意味を伝える。
過去の結果には、[送信履歴](#過去のラウンド)を引き続き添え、操作を促す案内は出さない。
送信履歴のない古い記録でも、操作を促す案内には戻さない。

送るボタンは「この結果で進める」にする。気になる決まったことがあれば、結果の中から「見直す」を押せる（[見直す](#見直す)）。結果の中の「見直す」も、ほかの場所と同じく、押すとすぐ LLM に届く。
見直し中の決まったことがあるときは、送るボタンを「見直しを頼む」にする。

成功条件: 問いのないラウンドを出すと、完成図と決まったことの一覧が出て、「この結果で進める」で送れる。結果の中で見直すを選ぶと、送る前に LLM に届き、送るボタンが「見直しを頼む」に変わる。送信後と議題の終了後も、完成図と決まったことを確認でき、見出しの案内は操作を促さない。
反例: 問いのないラウンドで、送るボタンだけが出る。送信後も「見直す」を押すよう案内する。
確かめ方: 画面の自動テスト。

### 直したこと

レビューのラウンドでは、LLM がレビューの指摘のうち、記録から導けるものを直して、その一覧を出す。
各項目には、何を直したかと、直した決まったことがあれば前と後を出す。
一覧は見るだけ。決まったことを直した項目には「見直す」を置き、違っていれば次のラウンドで問い直してもらえる。

成功条件: 直したことが問いとは別の欄に並び、決まったことを直した項目で見直すを押せる。
反例: 直したことが、答えを求める問いとして並ぶ。
確かめ方: 画面の自動テスト。

## 図

既存図パーツと完成図は、点・線・格子上の位置をテキストで書く。画面はその位置どおりに描き、並べ替えない。
新しいシーケンス図とフローチャートには [説明パーツの明示配置](explanation-parts.md#明示配置と固定規則) を適用し、この既存図の描画方式は変えない。
線の名前は線と重ならない場所に出す。同じ 2 点の間に逆向きの線があるときは、重ならないようにずらす。

成功条件: LLM が書いた格子の位置どおりに点が並び、線の名前が読める。
反例: 自動配置で、点や線の名前が重なる。
確かめ方: 画面の自動テスト（同じテキストから同じ位置に描かれることを確かめる）。

## 過去のラウンド

ラウンドを選ぶと、答えたときのカードと仮決めの一覧がそのまま出る。各問いには次のものが出る。

- 選んだ選択肢と、推奨だったもの
- 補足と、先送りのラベル
- 判子（本人が押した判子も代決の判子も、答えたときのまま日付付きで。[判子](#判子)）
- 質問と LLM の返事（図を含む）
- そこで決まったこと

「そこで決まったこと」は、そのラウンドで決まったときの中身で出す。あとで改めたものには、改めたことの印を付ける。
前提知識、選択肢の詳細説明、返事のパーツは、内容、種類、立場、読み順をそのラウンドのまま出す（[説明パーツの受理と保存](server.md#説明パーツの受理と保存)）。
過去のラウンドでは、答えを変えられない。変えたいときは [見直す](#見直す) を使う。

結果のラウンド（[結果](#結果)）を選ぶと、そのときの完成図と記録（決まったこと、作らないもの、見送った案、未決、任せたこと）を、そのラウンドで送られたときの中身のまま出し、どう送ったか（この結果で進めた、または見直しを頼んだ）を添える。どう送ったかは、そのラウンドの記録（[状態データ](server.md#状態データ)）から出す。送るボタンは出さない。結果に並ぶ決まったことにも、「見直す」を出す。過去のラウンドから「見直す」を押すと、その決まったことの今の中身（識別子が同じもの）が見直し中になる。

成功条件: 過去のラウンドで、前提知識、選択肢の詳細説明、返事のパーツと判子が、そのラウンドと同じ内容、立場、順序で出る。結果のラウンドを選ぶと、あとで完成図や未決が変わっていても、そのときの完成図と記録とどう送ったかが出て、送るボタンは出ず、決まったことの横に「見直す」がある。あとで改めた決まったことを過去のラウンドから見直すと、今の中身が見直し中になる。
反例: 要約しか出ない。質問の返事が消えている。過去の結果のラウンドから、もう一度送れる。過去の結果に、今の完成図や今の未決が出る。
確かめ方: 画面の自動テスト。

## 地図

地図は、決まったことのつながりを見せる。画面が [状態データ](server.md#状態データ) から組み立てる。LLM は地図を描かない。

### 点と線

- **点**: 決まったことと、今のラウンドの問いの 2 種類。決まったことの点には、どの問いで決まったかを同じ点の中に出す。ひとつの問いから複数の決まったことが出たときは、それぞれの点に同じ問いを出す。今のラウンドの問いは、今のラウンドの列に出す。
- **線**: 決まったことから、それを前提にした決まったことや問いへ引く。線の名前は、線の先の決まったことが決まった問い（線の先が今のラウンドの問いなら、その問い）にする。
- **見送った案**: その案を見送った問いの前提から、点線で出す。その問いに前提がなければ、その問いのラウンドの列に線なしで出す。
- **列**: ラウンドごとに並べる。列の見出しには、そのラウンドの話題を出す。話題は LLM が書く。列の中の縦の順は、線の交差が減るように画面が決める。

成功条件: 点に、決まったことと問いの両方が読める。見送った案が点線で区別される。
反例: 点に番号だけが出る。決まったことだけが出て、何の問いの話かわからない。
確かめ方: 画面の自動テスト。

### 道筋と全部

地図の範囲は 2 つある。

- **道筋**: 選んだ問いまたは決まったことから、前提をさかのぼってたどれる点と、その途中の問いで見送った案だけを出す。
- **全部**: すべての点を出す。全体の説明に使う。点や線の名前の重なりを減らす工夫をする。

成功条件: 道筋では、選んだ点の前提にならない点が出ない。
反例: 道筋に、関係のない点が出る。
確かめ方: 画面の自動テスト。

### 詳しい情報の出し方

点にカーソルを合わせたとき、フォーカスしたとき、タップしたときに、決まったことの全文、問い、そのときの答えが出る。
フォーカスした点が表示されている範囲の外にあるときは、その点が見えるまで図を動かす。
情報はほかの部分に重ねて出し、画面のほかの部分の位置は動かさない。

成功条件: カーソルを合わせる前と後で、地図や見出しの位置が変わらない。点にフォーカスしても情報が出て、範囲の外の点にフォーカスすると、その点が見える位置まで図が動く。
反例: 情報の欄の高さが変わって、地図が上下にずれる。
確かめ方: 画面の自動テスト。

### 移動と現在地

点やリンクで移動したら、元の場所へ戻れる。移動先では、今いる場所を目立たせる。

戻り先は、点・リンク・トーストの「見る」・判子のない問いへ移るボタンで移ったときに、移る前の場所を積む。手でタブを切り替えても積まない。ヘッダーの「戻る」は、最後に積んだ戻り先へ戻り、それを取り除く。戻り先がもうないとき（消えたカードなど）は、その戻り先を捨てる。ブラウザの戻るとは結び付けない。

成功条件: 地図から過去のラウンドへ移動したあと、戻る操作で地図の元の表示（範囲と選んだ点）に戻れる。2 回移ってから 2 回戻ると、移る前の順に戻る。手でタブを切り替えただけでは「戻る」が出ない。
反例: 移動すると戻る手段がない。移動先でどのカードに来たのかわからない。タブを切り替えるたびに戻り先が積まれ、「戻る」がタブを行き来するだけになる。
確かめ方: 画面の自動テスト。

### 見直しの目印

見直しで中身が変わった決まったことがあると、それを直接前提にしている問いと決まったことの点に目印を付ける。
LLM がラウンドで「そのままでいい」と確かめた点から、目印は消える（[見直しの問い直し](skill.md#見直しの問い直し)）。

成功条件: 中身が変わった決まったことを直接前提にしている点にだけ、目印が付く。
反例: 見直しのあとも、前提が変わった点が普段どおりに出る。
確かめ方: 画面の自動テスト。

## 完成図

完成図は、議題の最終形を 1 枚の図で見せる。LLM がラウンドを出すたびに描き直す（[完成図を描く](skill.md#完成図を描く)）。
描き方は [図](#図) と同じ。決まったことは、図の中の関係する場所に短い言葉で貼る。まだ決まっていない場所は、点線の空き枠で出す。

成功条件: ラウンドが進むと、空き枠が決まったことに置き換わっていく。
反例: 決まったことが、図の外にリストで並ぶ。
確かめ方: 人が実物で確かめる（中身の良し悪しは LLM の書き方による）。

## 決まったこと

「決まったこと」タブには、次のものを並べる。

- 決まったこと（代決のまま送った仮決めから決まったものには「代決」の印を付け、本人が判子を押したものと見分けられるようにする。見直しで問い直して改めた決まったことは、本人が答えたものとして印を外す）
- 作らないもの
- 見送った案（理由つき）
- 未決（決める人つき）
- 任せたこと（理由つき）
- 改めたこと
- 見直し中のもの

成功条件: 7 つの欄がそろって出る。代決のまま送った仮決めから決まったものには「代決」の印が付き、見直しで改めると印が外れる。
反例: 代決で決まったものと、本人が判子を押して決まったものが見分けられない。
確かめ方: 画面の自動テスト。

### 見直す

決まったことのそばには、どのタブでも「見直す」を置く。
押すと、軽い確認を出す。確認では、LLM に伝えて次のラウンドで問い直してもらうことと、LLM が見直しの結論を出すまではやめられることを示し、「見直す」か「見直さない」を選ばせる。
今のラウンドが結果で、その送るボタンが出ているときに結果の中の「見直す」を押したときだけ、確認の文面を「見直しを頼むで送ると、次のラウンドで問い直されます」にし、LLM が見直しの結論を出すまではやめられることも示す。過去の結果から押した「見直す」には、ふつうの確認を出す。
確認で「見直す」を選ぶと、その決まったことは見直し中になり、送信を待たずに LLM へ届く。
ラウンドを送ってから次のラウンドが届くまでは、「見直す」を押せない（「この結果で進める」で送ったあとは、議題を終えるまで押せない）。
「見直しをやめる」は、LLM がその見直しの結論を渡すまで使える。「見直しをやめる」には確認を出さず、押すとすぐ効く。
LLM は次のラウンドで問い直す（[見直しの問い直し](skill.md#見直しの問い直し)）。
見直し中の決まったことは、問い直して答えが出るまで、前提の行と地図で見直し中の印を付けて出す。

成功条件: 「見直す」を押すと確認が出る。確認で「見直す」を選ぶと見直し中になり、待っている LLM にすぐ届く。確認で「見直さない」を選ぶと何も変わらない。「見直しをやめる」を押すと、確認なしで元に戻る。送ったあと次のラウンドが届くまでは「見直す」が押せず、「見直しをやめる」は押せる。過去の結果から押すとふつうの確認が、今の結果から押すと結果用の確認が出る。
反例: 見直してほしいことを、ターミナルで言うしかない。押し間違えた「見直す」が、そのまま LLM に届く。送ったあとに押した「見直す」が、LLM に読まれないまま残る。
確かめ方: 往復のテストと画面の自動テスト。

## 作らないもの

- 推奨と答えた割合などを数える仕組み。成功は本人の体感で判断する。判子の数や代決の割合も、数えて集計はしない。
- 判子の見た目の細かな作り直し。本人が実物で見て決める（[未決](#未決)）。
- ヘッダーで返事待ちの件数や待ちの種類を細かく並べる表示。
- 個別質問の返事待ちへの 3 分後の確認案内。[質問](#質問) のカード内の表示は変えない。
- 送信成功を確認できないときの専用表示、再確認操作、自動再送。確認、拒否、通信エラーの扱いは変えず、通信切断だけで成功や失敗を断定しない。

## 見送った案

- 人が決める問いに初期値を入れない: わからないときに推奨に任せるのは、必要な逃げ道。
- 「わからないから任せた」を推奨の選択と区別する: わからないのか面倒なのか、本人にも区別できない。
- 区分を 3 段階にする: 真ん中の段が、どっちつかずの置き場になる。
- 前提でたどる木で、つながりを見せる: 非常に見づらい。
- 番号だけの点で、つながりを見せる: 何の情報かわかりにくい。
- 最終形を文章や、文と名前のリストで見せる: 中身を頭の中で組み立てる負荷が残る。
- 質問の返事を、画面の横の別の欄に出す: どの問いの話かを頭で追うことになる。
- 返事が来るまで次の質問をできなくする: 待ち時間が空白になる。
- 質問のやり取りを「最新だけ／全部／隠す」の 3 つの状態で切り替える: 設定の部品に見え、チャットとして不自然。隠したい場面はほぼない。
- 続きとして聞いたものを返信の木（入れ子）で出す: 時間の順と上下の順がずれ、字下げが深くなる。
- 決まった言い方のボタンで即座に送る: 押し間違えると取り消せない。
- Mermaid などの自動配置で既存図や完成図を描く: 縮尺が崩れ、点や名前が重なって見づらい。新しい説明図での不採用は [説明パーツの見送った案](explanation-parts.md#見送った案) に従う。
- 開いた・触ったで「見ずに送った」を記録する: たたんだカードでも読んで判断できるので、読んだかどうかを表さない。
- 「見ずに送った」の記録をやめるだけ（判子なし）: 内容を見ないまま送ることは減らない。
- 送る前に「まだ開いてない」の数だけ出す: 読んで送った問いも数に入る。
- 仮決めの行にも 1 つずつ本人が判子を押す: 仮決めの数だけ手間が増える。代決と後閲で 1 問 1 判子のまま手間を抑える。
- 人が決める問いだけに判子を付ける: 1 問に 1 判子の形が崩れる。
- 言語を OS の設定に合わせる: 本人が英語を既定に選んだ。
- 言語とテーマをブラウザや議題に覚えさせる: どの議題・どのブラウザでも同じにしたい。見た目の好みは壁打ちの記録ではない。
- 判子に日付を出さない: 承認した見た目どおりにし、いつ確かめたかを後から読めるようにする。
- 判子の日付を年-月-日で出す: 年をまたぐ議題はまずなく、判子が小さいまま読めるほうを取る。
- 判子の長押しで年と時刻を出す: 長押しできることに気づきにくい。
- 送ったあとも「見直す」を押せるままにし、1 ラウンド遅れて扱う: 扱いが 1 ラウンド遅れ、この結果で進めたあとは読まれないまま残る。
- 戻り先をブラウザの履歴と結び付ける: タブを移るたびに履歴が積まれる。
- 設定ファイルを読めない知らせを、ヘッダーの下の帯で出す: 画面の上の場所を取る。
- 確認で「次のラウンドが届くまではやめられる」と示す: 問い直しのラウンドを見てから、見直しをやめられなくなる。
- 結果用の確認の文面を、どこでも同じ 1 つにする: 「見直しを頼む」で送ることが伝わらない。
- wait がない間に「状態不明」を常時出す: 正常な処理中にも不安を煽る。
- 推定と断ったうえで作業中を出す: 送受信だけでは実際の稼働を確認できない。
- 送信後の上部案内も待ちフッターと併せて残す: 同じ案内が重複する。

## 未決

- 見た目の細部（カードや地図の余白、色、文字の大きさ、全部の範囲での重なりの減らし方、判子・ヘッダーの見た目）。最初の形を作ったあと、本人が実物を使いながら決める（決める人: 本人）。説明パーツの枠、ヘッダー、文字と領域の基準は [コードの表示](explanation-parts.md#コードの表示) と [新しい図の表示](explanation-parts.md#新しい図の表示)、説明図、地図、完成図の操作部分のまとまりは [図の操作部分](interaction.md#図の操作部分) で決まっており、この未決には含めない。配色や余白の細部と実物による判断は、それぞれのリンク先に従う。

成功条件: 説明パーツの決まった基準を未決として変更せず、残る見た目の細部は本人が実物で判断できる。
反例: 全画面の文字サイズが未決という理由で、新しい図の文字を自動縮小する。
確かめ方: 説明パーツの表示テストと、未決の細部の人による実物確認。

## 任せたこと

- 待ちフッターの配色、寸法、アニメーション周期の細部: [待ちフッターの見た目](#待ちフッターの見た目) の控えめな強調を保ち、既存のテーマと余白に合わせる。実装後の画面で人が確かめる。
- 送信後の短い案内の文面の細部: [送ったあとの知らせ](#送ったあとの知らせ) の送信完了と待つ対象の区別を保ち、実際の稼働や停止を断定しない。英語への翻訳も同じ意味にする。
- この仕様と [操作と知らせ](interaction.md) で日本語の文言を決めたもの（「LLM への質問（件数）」「この返事に続けて質問」、結果の中の見直すの確認、トーストの文言と「見る」、「Ctrl＋ホイールで拡大」など）の英語の文言: 同じ中身で、実装の計画で決める。英語の言い回しで振る舞いは変わらない。
