# 画面

shoryo の画面では、壁打ちの問いを読み、聞き返し、答える。
CLI の対話に問いが大量に流れてくる状態をなくし、問いのつながりと最終形を頭の中で組み立てなくて済むようにする。
画面が描くデータと、LLM との往復は [起動と往復と記録](server.md) にある。
問いや説明の中身を LLM がどう書くかは [shoryo skill](skill.md) にある。

用語は [CONTEXT.md](../../CONTEXT.md) に従う。

## 画面の構成

画面には次の 4 つのタブがある。

- 今のラウンド
- 過去のラウンド
- 地図
- 決まったこと

画面の上部には、議題の題名を出す。そもそもの議題（本人の言葉）は、開くと読める。
完成図は、どのタブからでも開ける。

画面に最初から書いてある文言（ボタン、見出し、タブ名など）は英語にする。
問い・選択肢・説明など、LLM が書く中身は、書かれた言語のまま出す。

成功条件: 4 つのタブがあり、固定の文言がすべて英語で出る。
反例: ボタンが日本語で出る。言語の切替が出る。
確かめ方: 画面の自動テスト。

## 今のラウンド

### 並び

今のラウンドは、上から次の順に並ぶ。

1. 直したこと（レビューのラウンドのときだけ。[直したこと](#直したこと)）
2. 人が決める問いのカード
3. 仮決めの一覧
4. 「まとめて送る」

成功条件: 人が決める問いと仮決めが、混ざらずにこの順で出る。
反例: 仮決めの問いが、人が決める問いと同じ形のカードで並ぶ。
確かめ方: 画面の自動テスト。

### たたんだカード

カードは最初、たたんだ状態で出る。たたんだカードには次のものを出す。

- 問いの文と、「人が決める」の印
- なぜ今決めるか（1 行）
- 前提の行（[前提の行](#前提の行)）
- 選択肢と、推奨の印
- 選んでいる答えの結果（[この答えだと](#この答えだと)）
- まだ開いていなければ、その印（[まだ開いてない印](#まだ開いてない印)）

カードを開くと、次のものも出る。

- 前提になっている決まったことの全文
- 前提知識
- 選択肢ごとの説明

成功条件: 開く前に上のものが見え、開くと残りの 3 つが加わる。
反例: 開かないと推奨がどれかわからない。開く前から前提知識の全文が出ていて、カードが長い。
確かめ方: 画面の自動テスト。

### 答え欄の初期値

答え欄には、最初から推奨の選択肢が選ばれている。補足を書く欄もある。

成功条件: 何も触らずに送ると、すべての問いが推奨で答えたことになる。
反例: 人が決める問いだけ、何も選ばれていない。
確かめ方: 画面の自動テスト。

### この答えだと

選んでいる選択肢の結果を、選択肢の下に出す。選択肢を変えると、その場で中身が変わる。
結果の文は、LLM が選択肢ごとに書く。

成功条件: 選択肢を切り替えると、結果の文が切り替えた選択肢のものに変わる。
反例: 送るまで結果が見えない。
確かめ方: 画面の自動テスト。

### 前提の行

カードには、その問いが前提にしている決まったことを、短い名前でつないで出す。
問いが直接前提にしている決まったことから始めて、それを決めた問いの前提へさかのぼり、3 つまでつなぐ。
さかのぼった先の問いに前提が複数あるときは、記録に書かれた順で最初の前提をたどる。
直接の前提が複数あるときは、前提ごとの並びを区切って横に並べる。
例: 「まとめて送る・聞き返せる ← まず UI を確定 ← 成功は体感で判断 ／ 見やすさが最重要」

名前をクリックすると、その決まったことの全文と、どの問いで決まったかが出る。
見直し中の決まったことには、見直し中の印を付ける。

成功条件: 番号ではなく短い名前で並び、クリックで全文と出どころの問いが出る。
反例: 「A12 ← A11」のように番号だけが並ぶ。前提が木の形で広がる。
確かめ方: 画面の自動テスト。

### 仮決めの一覧

仮決めの問いは、一覧にまとめて出す。各行には、問い、推奨が入った選択、選択の結果を出す。
行を開くとカードになり、聞き返し、先送りのラベル、補足が使える。

人は、どの問いも「人が決める」と「仮決め」の間で入れ替えられる。入れ替えはその場で反映され、問いはカードと一覧の間を移る。

成功条件: 仮決めの選択を一覧のまま変えられる。行を開くと聞き返せる。入れ替えると、カードと一覧の間を移る。
反例: 仮決めは一覧の中で変えられない。人が仕分けを直せない。
確かめ方: 画面の自動テスト。

### 聞き返し

カードの下で、その問いについて LLM に聞き返せる。聞き方は 3 つある。

- 決まった言い方のボタン（Explain more、Simplify with a diagram、What does the recommendation mean? など）を押す
- 自由に書いて聞く
- 返事をひとつ選んで、その続きとして聞く

聞き返しを送ると、そのカードに「書いている」と出る。返事が届いたら、そこに出る。
返事を待っている間も、ほかのカードを読んだり、答えたり、聞き返したりできる。
送る前なら、同じ問いに何度でも聞き返せる。

やり取りの出し方には 3 つの状態があり、人が切り替える。最初は「最新だけ」。

- **最新だけ**: いちばん新しい 1 往復（聞いたことと返事）だけを出す。
- **全部**: 続きとして聞いたものも含めて、返信の木を全部出す。
- **隠す**: やり取りを出さない。

返事には図を含められる（[図](#図)）。

成功条件: 2 つの問いに続けて聞き返し、どちらの返事も届く前にほかのカードを操作できる。返事はそれぞれのカードの下に出る。
反例: 返事が届くまで画面を操作できない。返事が画面の横の別の欄に出る。
確かめ方: 画面の自動テスト（LLM の返事は往復のテスト用の入力で代える）。

### 先送りのラベル

どのカードでも、「次のラウンドで聞き直して」のスイッチを入れられる。選択肢とは別のスイッチ。
入れたまま送ると、選んでいる選択肢は答えとして扱わず、その問いは決まらずに残る。
LLM は次のラウンドで、聞き方を変えて出し直す（[聞き直し](skill.md#先送りされた問いの聞き直し)）。

成功条件: 先送りを入れて送った問いは、決まったことにならない。
反例: 先送りを入れても推奨で決まる。
確かめ方: 往復のテスト。

### まだ開いてない印

人が決める問いのカードを一度も開かず、選択肢・補足・聞き返し・先送りのどれにも触っていない間は、カードに「まだ開いてない」印を出す。
仮決めから人が決める問いへ入れ替えた問いも、触っていなければ印を出す。一度触ったら、選択肢を推奨に戻しても印は戻らない。
「まとめて送る」の横には、印が付いている問いの数を出す。

印が付いたまま送っても、その問いは答えたことになる。ただし、見ずに送ったことを記録に残す。
過去のラウンドと「決まったこと」タブでは、見ずに送った答えに印を付ける。

成功条件: 一度も開かずに送った問いが、過去のラウンドで「見ずに送った」とわかる。
反例: 送ったら印の情報が消える。印が付いているせいで送れない。
確かめ方: 画面の自動テスト。

### まとめて送る

「まとめて送る」で、今のラウンドの答えを全部まとめて LLM に送る。
答え欄の初期値（推奨）のまま送った問いも、答えたことになる。

送ったあとは、次のラウンドが届くまで、今のラウンドの答え・聞き返し・仕分けの入れ替えは使えない。
送る前に返事待ちだった聞き返しは、あとから返事が届けば、そのラウンドの記録に残る。

成功条件: 送ると、全部の問いの答えが 1 回で LLM に届く。送ったあとに遅れて届いた返事が、過去のラウンドで見られる。
反例: 問いごとに送る。送っていない仮決めが、決まったことになる。
確かめ方: 往復のテスト。

### 直したこと

レビューのラウンドでは、LLM がレビューの指摘のうち、記録から導けるものを直して、その一覧を出す。
各項目には、何を直したかと、直した決まったことがあれば前と後を出す。
一覧は見るだけ。決まったことを直した項目には「見直したい」を置き、違っていれば次のラウンドで問い直してもらえる。

成功条件: 直したことが問いとは別の欄に並び、決まったことを直した項目で見直したいを押せる。
反例: 直したことが、答えを求める問いとして並ぶ。
確かめ方: 画面の自動テスト。

## 図

LLM が書く図（聞き返しの返事の図と、完成図）は、点・線・格子上の位置をテキストで書く。画面はその位置どおりに描き、並べ替えない。
線の名前は線と重ならない場所に出す。同じ 2 点の間に逆向きの線があるときは、重ならないようにずらす。

成功条件: LLM が書いた格子の位置どおりに点が並び、線の名前が読める。
反例: 自動配置で、点や線の名前が重なる。
確かめ方: 画面の自動テスト（同じテキストから同じ位置に描かれることを確かめる）。

## 過去のラウンド

ラウンドを選ぶと、答えたときのカードと仮決めの一覧がそのまま出る。各問いには次のものが出る。

- 選んだ選択肢と、推奨だったもの
- 補足と、先送りのラベル
- 見ずに送った印
- 聞き返しと LLM の返事（図を含む）
- そこで決まったこと

「そこで決まったこと」は、そのラウンドで決まったときの中身で出す。あとで改めたものには、改めたことの印を付ける。
過去のラウンドでは、答えを変えられない。変えたいときは [見直したい](#見直したい) を使う。

成功条件: 過去のラウンドで、聞き返しの返事と図が、答えたときと同じ中身で出る。
反例: 要約しか出ない。聞き返しの返事が消えている。
確かめ方: 画面の自動テスト。

## 地図

地図は、決まったことのつながりを見せる。画面が [状態データ](server.md#状態データ) から組み立てる。LLM は地図を描かない。

### 点と線

- **点**: 決まったことと、今のラウンドの問いの 2 種類。決まったことの点には、どの問いで決まったかを同じ点の中に出す。ひとつの問いから複数の決まったことが出たときは、それぞれの点に同じ問いを出す。今のラウンドの問いは、今のラウンドの列に出す。
- **線**: 決まったことから、それを前提にした決まったことや問いへ引く。線の名前は、線の先の決まったことが決まった問い（線の先が今のラウンドの問いなら、その問い）にする。
- **見送った案**: その案を見送った問いの前提から、点線で出す。その問いに前提がなければ、その問いのラウンドの列に線なしで出す。
- **列**: ラウンドごとに並べる。列の見出しには、そのラウンドの話題を出す。話題は LLM が書く。列の中の縦の順は、線の交差が減るように画面が決める。

成功条件: 点に、決まったことと問いの両方が読める。見送った案が点線で区別される。
反例: 点に番号だけが出る。決まったことだけが出て、何の問いの話かわからない。
確かめ方: 画面の自動テスト。

### 道筋と全部

地図の範囲は 2 つある。

- **道筋**: 選んだ問いまたは決まったことから、前提をさかのぼってたどれる点と、その途中の問いで見送った案だけを出す。
- **全部**: すべての点を出す。全体の説明に使う。点や線の名前の重なりを減らす工夫をする。

成功条件: 道筋では、選んだ点の前提にならない点が出ない。
反例: 道筋に、関係のない点が出る。
確かめ方: 画面の自動テスト。

### 詳しい情報の出し方

点にカーソルを合わせると、決まったことの全文、問い、そのときの答えが出る。
情報はほかの部分に重ねて出し、画面のほかの部分の位置は動かさない。

成功条件: カーソルを合わせる前と後で、地図や見出しの位置が変わらない。
反例: 情報の欄の高さが変わって、地図が上下にずれる。
確かめ方: 画面の自動テスト。

### 移動と現在地

点やリンクで移動したら、元の場所へ戻れる。移動先では、今いる場所を目立たせる。

成功条件: 地図から過去のラウンドへ移動したあと、戻る操作で地図の元の表示（範囲と選んだ点）に戻れる。
反例: 移動すると戻る手段がない。移動先でどのカードに来たのかわからない。
確かめ方: 画面の自動テスト。

### 見直しの目印

見直しで中身が変わった決まったことがあると、それを直接前提にしている問いと決まったことの点に目印を付ける。
LLM がラウンドで「そのままでいい」と確かめた点から、目印は消える（[見直しの問い直し](skill.md#見直しの問い直し)）。

成功条件: 中身が変わった決まったことを直接前提にしている点にだけ、目印が付く。
反例: 見直しのあとも、前提が変わった点が普段どおりに出る。
確かめ方: 画面の自動テスト。

## 完成図

完成図は、議題の最終形を 1 枚の図で見せる。LLM がラウンドを出すたびに描き直す（[完成図を描く](skill.md#完成図を描く)）。
描き方は [図](#図) と同じ。決まったことは、図の中の関係する場所に短い言葉で貼る。まだ決まっていない場所は、点線の空き枠で出す。

成功条件: ラウンドが進むと、空き枠が決まったことに置き換わっていく。
反例: 決まったことが、図の外にリストで並ぶ。
確かめ方: 人が実物で確かめる（中身の良し悪しは LLM の書き方による）。

## 決まったこと

「決まったこと」タブには、次のものを並べる。

- 決まったこと（見ずに送った答えから決まったものには、その印を付ける）
- 作らないもの
- 見送った案（理由つき）
- 未決（決める人つき）
- 任せたこと（理由つき）
- 改めたこと
- 見直し中のもの

### 見直したい

決まったことのそばには、どのタブでも「見直したい」を置く。
押すと、その決まったことは見直し中になり、送信を待たずに LLM へ届く。次のラウンドが届くまでは、「見直したい」をやめられる。
LLM は次のラウンドで問い直す（[見直しの問い直し](skill.md#見直しの問い直し)）。
見直し中の決まったことは、問い直して答えが出るまで、前提の行と地図で見直し中の印を付けて出す。

成功条件: 押すと見直し中になり、待っている LLM にすぐ届く。やめると元に戻る。
反例: 見直したいことを、ターミナルで言うしかない。
確かめ方: 往復のテスト。

## 作らないもの

- 推奨と答えた割合などを数える仕組み。成功は本人の体感で判断する。見ずに送った印も、数えて集計はしない。
- 画面の言語切替。

## 見送った案

- 人が決める問いに初期値を入れない: わからないときに推奨に任せるのは、必要な逃げ道。
- 「わからないから任せた」を推奨の選択と区別する: わからないのか面倒なのか、本人にも区別できない。
- 区分を 3 段階にする: 真ん中の段が、どっちつかずの置き場になる。
- 前提でたどる木で、つながりを見せる: 非常に見づらい。
- 番号だけの点で、つながりを見せる: 何の情報かわかりにくい。
- 最終形を文章や、文と名前のリストで見せる: 中身を頭の中で組み立てる負荷が残る。
- 聞き返しの返事を、画面の横の別の欄に出す: どの問いの話かを頭で追うことになる。
- 返事が来るまで次の聞き返しをできなくする: 待ち時間が空白になる。
- Mermaid などの自動配置で図を描く: 縮尺が崩れ、点や名前が重なって見づらい。

## 未決

- 見た目の細部（カードや地図の余白、色、文字の大きさ、全部の範囲での重なりの減らし方）。最初の形を作ったあと、本人が実物を使いながら決める（決める人: 本人）。
