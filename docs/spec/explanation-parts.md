# 説明パーツ

前提知識、選択肢の詳細説明、質問への返事を、必要な順で読める部品として渡すための契約と表示規則を定める。
入力の検証と保存は [起動と往復と記録](server.md#説明パーツの受理と保存)、内容の選び方は [shoryo skill](skill.md#説明の表現を選ぶ)、拡大表示の操作は [操作と知らせ](interaction.md#新しい説明図の拡大表示) にある。

## 対象と読み順

説明は、種類を明示したパーツの列で表す。
種類は文章、コードブロック、シーケンス図、フローチャート、既存図とする。
前提知識、選択肢の詳細説明、返事本文は、それぞれこの列に統一し、従来の文章欄や返事の図欄と二重に持たない。
文章だけで済む説明も文章パーツとして渡す。
複数パーツを必要な順に並べられ、列の順だけを読み順とする。
文章を Markdown のコードフェンスなどから別の種類へ変換しない。

対象はカードを開いて読む前提知識と選択肢の詳細説明、質問への返事、および過去のラウンドでの同じ説明に限る。
たたんだカードの問いと「この答えだと」は短い文章のままにする。
完成図、地図、決まったことの記録本文とそれらの表示方式は変えない。
既存の独自形式の返事の図は既存図パーツとして列に置けるが、その描画と操作は [図](screen.md#図) と [地図と完成図を動かす](interaction.md#地図と完成図を動かす) の既存図の規則を保つ。

成功条件: 文章、コード、文章の説明と、図から始まる説明が指定順で読める。前提知識、選択肢の詳細説明、質問への返事に新パーツが出て、問いと選択結果、完成図、地図、記録本文の表示は変わらない。
反例: 文章を常に先頭へ移す。返事の旧図欄と列の両方に同じ図を出す。コードフェンスを文章から自動抽出する。
確かめ方: 画面の自動テストで、各対象箇所と過去のラウンドの読み順、展開前後、既存図と独立した画面機能を確かめる。

## パーツの内容と立場

文章パーツは本文を持つ。
コードブロックは本文と、言語または疑似コードであることを持ち、任意の題名を付けられる。
新しい図は短い題名と、対応する種類の構造データを持つ。
図とコードには、選択肢の案、説明用の例、確認済みの現状のいずれであるかを持たせ、画面でパーツと一緒に読めるようにする。
実コードもこの区別の対象とする。
既存図パーツも題名と立場を持つが、図の元データの描き方は変えない。
具体的な項目名と種類や立場の識別子は [任せたこと](#任せたこと) に従う。
立場の意味と合意の扱いは [説明の意味を確かめる](skill.md#説明の意味を確かめる) に従う。

成功条件: 図とコードを単独で見ても案、例、確認済みの現状を見分けられ、コードの言語または疑似コードの区別、図の題名を読める。
反例: 実コードに立場を出さない。確認済みの現状まで一律に案と表示する。
確かめ方: 3 つの立場を各図とコードで表示する画面の自動テスト。必須内容の欠落は [入力の検証](server.md#説明パーツの受理と保存) で確かめる。

## 表示だけの安全境界

パーツはローカルに同梱した固定の描画処理で表示する。
送られた文章、コード、図のラベルや元データを HTML、SVG、スクリプトとして実行しない。
エージェントが渡す任意の HTML、SVG、描画コードは受け取らず、構造データから描く。
パーツ由来の外部画像などを読み込まず、外部リンク機能を追加しない。
実コードも読み物として表示し、実行や編集の操作を設けない。

成功条件: 実行を意図した文字列を本文やラベルに含めても文字として読め、コード実行も外部素材への通信も起きない。禁止形式の入力は拒否される。
反例: SVG をそのまま挿入する。コードを実行するボタンや外部画像の読み込みを設ける。
確かめ方: 入力境界の自動テストと、画面の自動テストで DOM の実行、外部要求、実行や編集の操作の不在を確かめる。

## シーケンス図の表現範囲

シーケンス図は登場人物の左右順と出来事の上下順、登場人物間のメッセージ、自己呼出しを表す。
戻りのメッセージは線の違いで区別できる。
条件分岐と繰り返しは条件を読める枠で表す。
枠は入れ子にせず、複雑な説明は図を分ける。
並行実行、厳密な時間軸、実行中を示す棒は扱わない。

成功条件: 指定した登場人物順と出来事順、自己呼出し、戻り、分岐条件、反復条件を区別して読める。入れ子の枠は入力で拒否される。
反例: 戻りが通常のメッセージと区別できない。分岐と反復の条件が消える。
確かめ方: 入力の自動テストと、各表現を含む画面の自動テスト。意味の適切さは [説明の意味を確かめる](skill.md#説明の意味を確かめる) で人が確認する。

## フローチャートの表現範囲

フローチャートは開始、終了、四角い処理、ひし形の判断を区別する。
判断から出る枝には条件ラベルを必須とする。
合流と前の処理への戻りを表せ、矢印の経路を明示して指定できる。
担当者ごとの帯や自由な図形は扱わない。

成功条件: 開始と終了、処理と判断を区別でき、判断から出る各枝の条件を読める。合流と戻りが指定した接続を保つ。
反例: 判断と処理を同じ四角にする。条件のない判断の枝を受け付ける。
確かめ方: 条件欠落を拒否する入力の自動テストと、形状、接続、条件を確かめる画面の自動テスト。

## 明示配置と固定規則

新しい図は、配置、間隔、フローチャートの矢印の経路を、限定した構造データで指定できる。
シーケンス図では登場人物と出来事の順序を、フローチャートでは節点の位置を保つ。
指定を省略した箇所には固定した規則を適用し、画面は節点の順序や位置を自動で変更しない。
文字の折り返しや箱の寸法の算出は、節点の再配置とは区別する。
具体的な座標、間隔、経路の指定方法と省略時の規則は [任せたこと](#任せたこと) に従う。
Mermaid は採用しない。

成功条件: 同じ構造データと同じ表示条件から同じ配置を得られ、指定した順序、位置、間隔、経路が保持される。省略時も宣言した固定規則で描かれる。
反例: 重なりを避けるため節点を勝手に移す。表示幅に応じて登場人物の順を入れ替える。
確かめ方: 実装計画で宣言した指定方法と省略規則の受入テスト、および表示幅を変える画面の自動テスト。

## 配置の失敗の検出

新しい図では、描画される箱とラベルの領域、文字の収まり、矢印の経路を検査する。
独立した節点の箱同士の重なり、ラベル同士やラベルと無関係な箱との重なり、図の描画領域や箱からの文字の切れ、矢印が無関係な箱の内部を通る問題を検出する。
スクロールで見える範囲の外にあることは、文字の切れとは区別する。
検出した図は正常な説明図として扱わず、[描画失敗の表示](#描画失敗の表示) にする。
位置を勝手に直して正常扱いにしない。

すべての接触や包含を重なりの失敗とは扱わない。
箱に所属する文字が箱の内側に収まること、矢印が接続先と接続元の箱に接すること、自己呼出しの折り返し、分岐や反復の枠がその内容を囲むことは、合法な表現として区別する。
所属するラベルでも、文字が切れたり別の文字を覆ったりすれば検出対象とする。
線同士の交差だけを一律に禁止する約束はしない。
これらの検査は検出可能な配置の問題を対象とし、意味の正しさや完全な美しさを保証しない。

成功条件: 各失敗の例を検出し、合法なラベルの所属、接続、自己呼出し、枠内の内容を誤って拒否しない。
反例: 箱内の本文をすべて重なりとして拒否する。矢印が無関係な処理を横切る図を正常扱いにする。
確かめ方: 各失敗と合法な表現を対にした描画検証の自動テスト。実際の文字計測を用いる画面の自動テストで、長いラベルと両テーマも確認する。全体の読みやすさは人が実物で確認する。

## 描画失敗の表示

受理後に新しい図を描けない場合は、そのパーツの場所に原因と読める元データを出す。
他のパーツとカードは読める状態に保つ。
パーツを黙って消したり、不完全な図を正常な図として出したりしない。
入力で分かる不正をこの表示で済ませることはせず、[受理の規則](server.md#説明パーツの受理と保存) に従う。

成功条件: 図の表示が失敗しても、その位置に原因と元データがあり、前後の文章と他のカードを読める。
反例: エラーをコンソールだけに出す。失敗したパーツを飛ばして説明を続ける。
確かめ方: 描画失敗を起こす画面の自動テストで、原因、元データ、周囲の表示と操作を確かめる。

## コードの表示

コードは等幅で、字下げと改行を保持する。
長い行を勝手に折り返さず、本文をそのままコピーできる。
未知の言語でも同じ読み方ができる。
最初の基準は本文 14px 相当、最大高さ 320px とし、画面高さの半分も上限とする。
短いコードは必要な高さだけ使い、長いコードは領域内の縦横スクロールで読む。
狭い画面でも文字を自動縮小せず、ブラウザの文字拡大を妨げない。
構文色分けは必須にしない。

成功条件: 字下げと改行を含む本文を同一内容でコピーでき、長い行は折り返されない。短い内容は余分な高さを取らず、長い内容は両方の高さ上限内でスクロールできる。
反例: コピーで立場の表示まで混ざる。狭い画面に合わせて文字を縮める。未知の言語を拒否する。
確かめ方: 画面の自動テストで本文、コピー結果、文字サイズ、領域寸法、縦横スクロールを確かめる。ブラウザの文字拡大を妨げないことは人が実物で確認する。

## 新しい図の表示

新しい図の文字は最初の基準を 14px 相当とし、カード内の最大高さは 360px、画面高さの半分も上限とする。
短い図は必要な高さだけ使う。
カード幅に収まらない図を無理に縮めず、領域内のスクロールで読む。
狭い画面でも文字を自動縮小せず、ブラウザの文字拡大を妨げない。
別の拡大表示で移動と拡大縮小ができる（[拡大表示の操作](interaction.md#新しい説明図の拡大表示)）。

成功条件: 広い図は文字サイズを維持して領域内でスクロールでき、両方の高さ上限を守る。短い図は必要な高さだけ使い、拡大表示を開ける。
反例: 全体をカードに入れるため文字まで縮める。図の高さでページ全体を埋める。
確かめ方: 広い図と短い図を、通常幅と狭い幅、異なる画面高さで表示する画面の自動テスト。ブラウザの文字拡大は人が実物で確認する。

## 作らないもの

- 比較表と diff の専用パーツ。今回の追加はコードと順序、分岐の説明に限る。
- 完成図、地図、記録本文への新パーツ追加（[対象と読み順](#対象と読み順)）。
- コードの実行と編集、自由な HTML、SVG、スクリプト、外部素材と外部リンク（[安全境界](#表示だけの安全境界)）。
- シーケンス図の入れ子、並行実行、厳密な時間軸、実行中の棒と、フローチャートの担当者の帯、自由な図形（[シーケンス図](#シーケンス図の表現範囲)、[フローチャート](#フローチャートの表現範囲)）。
- 視覚で図を追えない人向けの専用文字一覧の生成、代替文章の必須化。今回の説明表示の対象から外すが、[既存の操作の約束](interaction.md#操作の約束) と描画失敗の表示は維持する。ターミナルの読み上げで十分であるとの保証も加えない。
- 構文色分けの必須化（[コードの表示](#コードの表示)）。

成功条件: 追加したパーツと操作が宣言した範囲に収まり、対象外の機能を前提にせず読める。
反例: 図の代替文章を必須にするため入力を拒否する。新パーツを完成図にも使わせる。
確かめ方: 入力と画面の自動テスト、および実装差分の範囲を人が確認する。

## 見送った案

- コードだけに絞る、返事だけで使う方式は、順序と分岐、および回答前の理解も助けたいため採用しない（[対象と読み順](#対象と読み順)）。
- 文章の後にパーツ 1 個だけを出す方式と、旧文章、旧図、新パーツの順で欄を足す方式は、必要な読み順を表せないため採用しない。
- Markdown からパーツを読み取る方式は、種類と立場と順序を明示して検証するため採用しない。
- Mermaid の自動配置は、配置の崩れ、調整の難しさ、不自然な縮尺の懸念を解消した証拠がないため採用しない（[明示配置](#明示配置と固定規則)）。
- 図を枠に収まるまで縮める方式は、文字を読める大きさに保つため採用しない（[図の表示](#新しい図の表示)）。
- 検出した崩れを警告だけで正常な図と一緒に出す方式、機械検出をせずスキルだけに任せる方式は、崩れた図を正常な説明として渡さないため採用しない（[配置の失敗の検出](#配置の失敗の検出)）。

成功条件: 読み順、明示配置、失敗表示が採用した方式のままである。
反例: 既存図と新しい図を区別せず Mermaid へ置き換える。
確かめ方: 各リンク先の受入テストと、採用方式を人が確認する。

## 任せたこと

内部の項目名、種類と立場の識別子、検証処理の分け方は、決めた意味と安全境界を変えない範囲で実装計画に任せる。
配置、間隔、経路の指定方法と省略時の固定規則も、実装前に計画で宣言し、受入テストで固定する。
有限の入力上限の具体値は [サーバーの任せたこと](server.md#任せたこと) に従う。
無制限、黙った切捨て、自動再配置、文字の自動縮小、表示基準や機能範囲の変更は裁量に含めない。
振る舞いの変更が必要なら本人に戻す。

成功条件: 実装計画に指定方法と省略規則が宣言され、その境界を確かめる受入テストがある。
反例: 指定方法や既定の配置を未定のまま実装し、画面側の推測で決める。
確かめ方: 計画を人が確認し、宣言した規則の自動テストを実行する。

## 未決

本人に残す未決事項はない。
実装の具体化は [任せたこと](#任せたこと) と区別し、承認していない挙動を追加しない。

成功条件: 実装計画で決める細部と、本人へ戻す振る舞いの変更を区別できる。
反例: 委ねられた命名を本人の未回答として扱う。新機能を委任済みと扱う。
確かめ方: 計画と仕様の対応を人が確認する。
